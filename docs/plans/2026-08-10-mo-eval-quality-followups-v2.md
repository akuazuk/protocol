## 2. Переосмысление (что было неверно в v1)

Кейс: визит `3600047`, мигрень, план с эсциталопрамом + суматриптаном + **мелоксикамом**.

| Гипотеза v1 | Факт |
|--|--|
| DDI тянут ЛС из анамнеза («Нимессил») | Нет: `_axis_safety` уже берёт только `treatment_recommendations` |
| Нужны ручки «Major DDI → Важно» в Настройках | Рано: без gold/калибровки это ломает доверие; методисту нужнее **честные findings** |
| Колонка приоритета во всех таблицах | Слабый ROI: рабочая поверхность - Очередь / Обзор; дублировать P-колонку = шум |
| Deep-rescore из UI как следующий шаг после ярлыков | Важно, но **после** фикса нормализации ЛС, иначе пересчитаем ту же ошибку |

**Корневой баг кейса:** `мелоксикам` нормализуется в INN **`diclofenac`** (override/seed, confidence 0.98). Отсюда ложный Moderate DDI `diclofenac + escitalopram`. Реальный Major `escitalopram + sumatriptan` при этом остаётся правильным поводом для **Важно**.

## 3. Цель v2

Методист на кейсе вроде 3600047 видит:

1. одно **Важно** по суматриптан + эсциталопрам (с цитатой из плана);
2. при необходимости **Умеренно** по мелоксикам + эсциталопрам (НПВП+SSRI), **без** слова diclofenac;
3. пустые блоки обследования/наблюдения - **Оформление**, не раздувают «критичность»;
4. в Настройках понимает: потолки = «насколько сильно режем балл», а не «что считать критичным».

## 4. Канон приоритетов (без изменений)

| Код | UI | Когда |
|--|--|--|
| P0 | Критично | риск вреда / hard defect → status `critical`, cap |
| P1 | Важно | Major DDI, red flag, сильный clinical/safety |
| P2 | Умеренно | Moderate DDI и аналоги |
| P3 | Оформление | дыры блоков, форма |

Очередь разбора - по **whitelist кодов** (`mo-action-queue-precise-signals-v2`), не по любому Важно.

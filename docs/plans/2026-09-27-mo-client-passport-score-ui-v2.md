## 2. Что будет (целевая картина)

Три слоя. Их нельзя смешивать в одном job.

```text
А. Карта           205 452 клиента     индекс визитов + анализы
Б. Оценка 2026     дыры ~52 000        зоны + итог, без LLM
В. Разбор          любой оценённый     5 шагов, паспорт на фоне
```

**А.** У каждого id - паспорт: покрытие, плитки специальностей, индекс
всех визитов (дата, врач, МКБ, оценка если есть), индекс анализов,
открытые отклонения, сигналы для текущего визита. Тексты КЗ в паспорт
не кладём. Дубль режет пара `(patient_key, visit_id)`.

**Б.** Сентябрь не пересчитываем. Считаем январь → февраль → март →
добить апрель и июль. На уже лежащих текстах склада. LLM не включаем.
После смены шкалы (H3-prep) - пересчёт с даты релиза, не январь-июнь
задним числом без `evaluator_version`.

**В.** Вместо скролла: Пациент → Линза → Визит → Доказательство → Решение.

Последний визит 2026 оценивается **на фоне паспорта** (в т.ч. визиты до
2026, если они в карте). Старые визиты картой есть, оценкой нет - так
и надо.

## 4. Интерфейс: пять шагов

На экране один шаг. Крошки сверху. Назад = предыдущий шаг. Список случаев
не пропадает.

```text
1 Пациент → 2 Линза → 3 Визит → 4 Доказательство → 5 Решение
```

**Шаг 1. Пациент.** N визитов, M специальностей, первая-последняя дата.
Плитка на специальность: N, последняя дата, МКБ, оценка. Плитка анализов:
дат, открытых отклонений. Плитка текущего визита. Одна строка контекста.
Нет ключа - «оцениваем только этот визит», сразу шаг 3. PHI нет.

**Шаг 2. Линза.** Все / одна специальность / анализы. 12 строк, «Ещё 12».
Клик по дате анализа открывает этот день на том же шаге.

**Шаг 3. Визит.** Итог + причина. Три чипа зон с первой причиной
(«план как 12.08», «КП не подобран - не штрафуем»). До 5 дефектов.
Контекст одной строкой. КП одной строкой. Без deep, №55, семейств %.

**Шаг 4. Доказательство.** Одно правило, одна цитата ≤ 240 знаков,
дефект / контекст / черновик, `evaluator_version`. Стрелки по списку.

**Шаг 5. Решение.** Оформление / Диагноз / План + комментарий + PDF.
CRM-статус здесь не живёт.

Вход из «Найти МО» - сразу шаг 3. Меню «Пациент» - шаг 1.
URL: `page=case&case_id=&step=&lens=&proof=`.  
Флаг отката: `MO_CASE_STEPS=0` вернёт старый скролл на 2 релиза.

## 5. Как собирается карта 205 тысяч и как не дублировать

Лёгкий extract с GCE (не полный `result`):

`patient_id` → `patient_key`, `visit_id`, дата, специальность, код МКБ,
короткий ярлык диагноза до 80 знаков. Анализы: дата, панель, признак
отклонения если уже умеем, без дампа всех цифр в индекс.

Пишем в `fact_mo_visit_index` (или сразу в паспорт) с уникальностью
`(patient_key, visit_id)`. Повторная выгрузка того же визита - REPLACE.
Несколько КЗ одного визита - одна карточка (клиническое, иначе свежее).

Полные тексты 2026 уже на складе в `fact_mo_case` по `mis_id`. Паспорт на
них ссылается, не копирует.

Обновление: ночь/кнопка дала новые строки → `DISTINCT patient_key` →
пересобрать только эти паспорта. Полный проход 205 тысяч - только если
сменилась схема индекса, вручную, не в 01:00-04:30.

Оценка старых визитов карты **не** запускается этим extract.

## 6. Как оценивается последний визит

Порядок:

1. Прочитать паспорт as-of даты визита.
2. Посчитать сигналы.
3. Зоны (с H3-prep).
4. Итог.
5. `context[]` отдельно от findings.

| Сигнал | Итог | Корзина в UI |
|--|--|--|
| открытое отклонение анализа, не в тексте | не выше «важно» (после меток) | дефект |
| тот же корень МКБ + та же спец. + тот же отпечаток плана | зона плана слабо | дефект |
| эпизод у другого специалиста за 180 дней, в тексте нет | зона диагноза слабо | дефект |
| результат после прошлого плана, слот пуст | оговорка | дефект |
| первый визит в специальности / код уже был у врача | не двигает | контекст |

Флаги: `MO_PASSPORT=1` строить; `MO_PASSPORT_IN_SCORE=0` пока тень;
после выборки 40+40 - `=1` решением владельца.

H3-prep (другие файлы, можно раньше): мягкие/жёсткие критерии оформления;
`D_reg55_gap` вне зоны 1; столбец `safety_band`.

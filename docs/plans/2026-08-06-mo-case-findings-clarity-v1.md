## 1. Контекст

В drawer «Разбор случая» методисту непонятно:

1. **«Открыть КП»** → JSON `{"detail":"Not Found"}` (битая ссылка `/proto`).
2. **«Развёрнутый разбор»** - textarea узкая (`max-width: 220px` у `.control`).
3. **P0 «Критический дефект по №55»** - не ясно *что* проверено и *почему* P0.
4. Тексты вроде «Требует проверки, что индивидуальные данные…» - шаблон из
   `dim_finding.why_important_ru`, не объяснение конкретного случая.
5. Источники сырые: `template_pair:…`, `DDInter`, `ISMP/клин.практика`.

### Корневые причины

| Симптом | Причина |
|--|--|
| Not Found на КП | `viewer_url = "/proto?path=…"`; маршрута нет. Нужен `/proto-viewer.html?path=…` |
| Узкий textarea | `.control { max-width: 220px }` без исключения для `#drawer-summary` |
| Неясный P0 №55 | В `mz_2021_55.json` единственный P0 - `no_unhandled_red_flag` с проверкой `status == manual_review_required` (круговая логика, не red flag) |
| «Требует проверки…» | Fallback `COALESCE(detail_ru, why_important_ru)` + шаблон dim для `E_template_copy` |
| Сырые источники | UI печатает `source_ref` as-is |

## 4. Решение по методике P0 (зафиксировано)

**P0** = риск вреда пациенту / критический дефект качества по смыслу постановления.

Не является P0:

- сам факт статуса `manual_review_required` / «требует проверки модели»;
- дефекты оформления без клинического риска (P2);
- отсутствие поля без red-flag контекста (обычно P1/P2).

Для оси №55 в v1:

1. Критерий `no_unhandled_red_flag` → severity **P1**, формулировка: «случай направлен
   на ручную проверку моделью» (не «критический дефект»).
2. Finding `D_reg55_p0` - только если failed-критерий с severity=P0.
3. Failed P1/P2 → `D_reg55_gap` с понятным RU, не маскировать под P0.
4. Пока в каталоге нет настоящих P0-критериев, P0 на оси №55 не создаём.

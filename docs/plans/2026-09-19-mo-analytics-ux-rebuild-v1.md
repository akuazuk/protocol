## 1. Контекст: какую работу делает человек

Методист за 2–3 минуты должен:

1. Найти **плохие** МО: критично / важно / слабо – по врачу, специальности, МКБ, болезни, анализу, назначению.
2. Найти **хорошие** МО того же врача / той же болезни – как эталон и для сравнения.
3. Открыть разбор и понять, *что* не так, не ожидая пустой панели.
4. Не думать, какой из 11 пунктов меню «настоящий» и какую из двух кнопок «Применить» нажать.

Сейчас кабинет это умеет только частично: поиск `I10` режет список, остальное либо врёт, либо пустеет на 7–16 секунд.

## 3. Целевой продукт (как должно ощущаться)

Один рабочий стол **«Найти МО»**. Не 11 почти одинаковых вкладок.

```text
┌──────── sidebar ──────┐  ┌──────── полоса поиска (всегда) ──────────────────────────┐
│ Обзор                 │  │ [поле: врач / МКБ / болезнь / визит]  [день▾] [сброс]     │
│ Найти МО   ← главный  │  ├──────────────────────────────────────────────────────────┤
│ Врачи                 │  │ Хорошо | С замечанием | Слабо | Важно | Критично | Все    │
│ Лекарства             │  │ Врач ▾  Спец. ▾  МКБ/диагноз ▾  Анализы ▾  Назначения ▾ │
│ Анализы               │  ├──────── список (скелетон, старые строки серые) ──────────┤
│ ── служебное ──       │  │ 50 строк сразу, total честный, пагинация/вирт. скролл     │
│ Отчёты                │  ├──────── инспектор справа (не модалка) ───────────────────┤
│ Протоколы МЗ          │  │ Документ | Оценка | КП     решение методиста снизу        │
│ Инструкции ЛС         │  └──────────────────────────────────────────────────────────┘
│ Справка               │
└───────────────────────┘
```

Правила ощущения:

1. Любой чип **сразу** меняет `total` и список. Нет черновика и второй «Применить».
2. Пока едет сеть: предыдущие строки остаются, сверху тонкий прогресс. Пустая таблица только если сервер честно вернул 0.
3. «Хорошие» и «плохие» – одна шкала `overall_grade` (critical / important / poor / fair / good), те же слова, что в колонке.
4. МКБ и текст диагноза – ось, не спрятанный `q=`.
5. Клик по врачу / специальности / коду анализа открывает **тот же** список с чипом, не другой мир с 0/0.
6. Разбор: скелетон сразу, текст МО < 500 ms, КП отдельным запросом.

## 5. Дизайн (визуал, не «ещё графиков»)

Опираться на уже существующие токены `mo-tokens.css`. Не вводить новую палитру «ради редизайна».

### 5.1. Иерархия

- **Первый взгляд:** полоса качества (5 кнопок) + поле поиска + число «N случаев».
- **Второй:** таблица. Колонки по умолчанию: Оценка · Дата · Врач · Спец. · МКБ · Диагноз · Оформление · Диагноз-зона · План · Причина. №55, полнота, надёжность – в «Колонки», выкл.
- **Третий:** инспектор. Никаких LLM-KPI и №55 на первом экране (канон ui-target §9).

### 5.2. Цвет оценки (одна легенда везде)

| Grade | Слово | Цвет токена | Где |
|--|--|--|--|
| critical | Критично | `--danger` | чип, колонка, KPI обзора |
| important | Важно | `--warn` | то же |
| poor | Слабо | `--warn` приглушённый | то же |
| fair | С замечанием | нейтральный акцент | то же |
| good | Хорошо | `--ok` | то же |
| na | Нет оценки | `--muted` | не прятать, фильтр «Без оценки» |

Запрещено: P0/P1 в таблице; английские `critical` в чипе (сейчас чип пишет сырой id).

### 5.3. Плотность и адаптив

- 1440×900: список + инспектор 55/45.
- 1280: инспектор поверх списка, не теряя выбранную строку.
- 768: меню иконками, фильтры – нижний sheet, не 677×351 выпадашка на 188 контролах.
- Поиск: минимум 360 px, placeholder целиком виден.

### 5.4. Состояния списка (обязательные)

1. Загрузка первой страницы: 8 серых строк-скелетон.
2. Обновление: старые строки `opacity: .55`, не `innerHTML = ""`.
3. Ошибка: баннер + кнопка «Повторить», строки не трогать.
4. Честный ноль: «Нет МО по фильтрам» + какие чипы стоят + «Сбросить оценку».
5. Неполный день: «Данные по ДД.ММ, покрытие N%» без ложного «источник 0».

### 5.5. Что убрать с глаз

- «Маршрут анализа» / drill trail на каждый клик графика – свернуть в Справку.
- Сравнение «предыдущий период» с главных фильтров – в Обзор.
- Zone presets на английских `zone2a` в чипах – переименовать в «Диагноз плохо».
- Команды ⌘K оставить, но подписи не обрезать («Провер…»).

## 7. Контракт фильтров (один query на все экраны)

Все экраны строят URL из одного объекта. Имена **совпадают** с Query FastAPI.

| Чип UI | Query | Где режется | Примечание |
|--|--|--|--|
| Период | `date_from` `date_to` / `month` | SQL `visit_date` | «Сегодня» = календарный день Минск, не «вчера» под видом сегодня |
| Оценка | `overall_grade` | SQL колонка + fallback compute | multi: `good\|fair` через `\|` |
| Без оценки | `overall_grade=na` | то же | отдельный чип |
| Врач | `doctors` | SQL `doctor_fio` / key | facets с поиском внутри |
| Специальность | `specializations` | SQL | без inner Apply |
| Филиал | `filials` | SQL | |
| МКБ | `icd` или `q` если код `\b[A-Z]\d{2}` | SQL `diagnosis_code` LIKE / IN | не ждать полнотекста |
| Диагноз текст | `q` | SQL + существующий поиск | |
| Глава МКБ | `mkb_chapters` | уже есть в `_MULTI_FILTERS`, **нет UI** | добавить facet |
| Анализы / ЛС | `finding_family` `finding_codes` | уже есть в `_filter_records` | чипы, не отдельные периоды |
| Очередь | `queue_only=1` | `_needs_review` + CRM не closed | не путать со `statuses` |
| Критично (оценка) | `overall_grade=critical` | **не** `statuses=critical` | починить кнопку |
| CRM | `crm_statuses` | отдельный popover «Статус разбора» | подпись не «Статусы» |
| Зона плохо | `zone` + `zone_band` | уже есть | пресеты сбрасывают CRM |

Приёмка контракта: таблица тестов в `tests/test_mo_cases_query_contract.py` – каждый чип меняет `total` на фикстуре из 20 строк.

Сейчас каждый `/cases?page=2` читает **весь** месяц.

1. SQL `WHERE` по `visit_date`, `specialty`, `doctor_key`, `filial`, `diagnosis_code`, `overall_grade`, `document_kind`.
2. `COUNT(*)` отдельным запросом (или window), не `len(filtered)`.
3. `ORDER BY visit_date DESC LIMIT page_size OFFSET …` в SQL.
4. Findings join не через `GROUP_CONCAT` всех кодов на весь месяц, если фильтр не по findings: отложенный join на page ids.
5. Индексы: `(visit_date, document_kind)`, `(doctor_key, visit_date)`, `(diagnosis_code, visit_date)`, `(overall_grade, visit_date)`. Миграция только через скрипт склада, не руками `data/`.
6. Цель p95 < 1.5 с на 8k строк; заложить путь на 100k (cursor `visit_date, visit_id`, не deep OFFSET).

Приёмка: curl с GCE `/api/methodist/mo/cases?month=2026-09&page_size=50` < 1.5 с; page=20 не медленнее page=1 в 10 раз.

Не включать `SYNC_PROTOCOL_CORPUS`. Не трогать night LLM с Mac.

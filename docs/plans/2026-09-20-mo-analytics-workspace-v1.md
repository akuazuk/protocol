## 1. Контекст: какую работу делает человек

Методист за 2-3 минуты должен:

1. Поставить **период** (день / неделя / месяц / свои даты) и сразу видеть тот же `total`.
2. Поставить **диагноз или МКБ**, врача, оценку - одним контролом, с крестиком снять.
3. Открыть случай **на всю страницу**, прочитать МО, записать решение, стрелками листать выборку.
4. Вернуться к списку с теми же фильтрами (браузер Back).
5. Найти **любой** визит или анализ из МИС, даже если ночной пайплайн его ещё не оценил, увидеть бейдж «в аналитике / не разобрано» и по кнопке отправить в склад.

W0-W7 это умеют частично: `overall_grade` и `icd=` уже режут склад. Остальное выглядит как фильтр, но либо режет 50 строк, либо спрятано, либо врёт цифрой.

### 2.2 Три независимых «фильтра» (корневая причина жалобы)

1. **Склад / URL** - `query()`: period, icd, overall_grade, врач, спец, queue_band. Это единственное, что меняет 8062.
2. **Панель `<details> Фильтры`** - период, сравнение, филиал, спец, врач, статусы CRM, оценка дублем, две кнопки Применить / Отмена / Сбросить. Календарь `#date-from` / `#date-to` **hidden**, пока не выбрать «Произвольный».
3. **Хром таблицы** (`ensureTableChrome`): `<select>` по уникальным значениям **уже загруженных 50 строк**. Подпись «Фильтр: ДАТА» / «Фильтр: ДИАГНОЗ». На page=1 дата только `2026-09-19`. Выбор не меняет `total=8062`, пишет «Показано N из 50». Две колонки с одним aria-label «Диагноз» (текст и зона).

Плюс полоса оценки и поиск в шапке - четвёртый вход в ту же выборку.

Итог для человека: «выбрал дату / диагноз - ничего не случилось с месяцем» - это не баг ощущения, это другая функция, названная тем же словом.

### 2.3 Разбор случая

Канон ui-target §9: широкая панель, шапка + 3 оценки + «Что не так» + текст + решение.

На проде 1440:

- `wideInspector()` = media 1440, панель **680 px** справа, список с `margin-right: 680px`.
- Таблица уезжает вниз, инспектор режет шапку. Это не split view Google Docs и не полный экран Linear.
- Вкладки «Документ / Проверка», блоки История / КП / Назначения / Замечания сразу на первом экране - против §9.11.

- Пользователь явно: открытие = **на всю страницу**.

### 2.4 Обзор врёт зерном

Зерно «Месяц» нажато, чип «текущий месяц». Карточки «Получено 310 / Оценено 252» - **рабочий день 19.09**. «Критично в очереди **0**» при API месяца = 13. Полоса оценки и поиск живут на месяце, плитки - на дне. Google Analytics так не смешивает date range и scorecard.

Обрезается: «Нет оцен», чип периода, «Сравнен…».

### 2.5 Карта кнопок (62 видимых на Обзоре 809 px, больше на 1440)

Слой навигации: Обзор, Найти МО, Врачи, Лекарства, Анализы, Ещё, плюс внутри Ещё Период / Очередь / Отчёты / КП / ЛС / Справка. «Период» в Ещё ведёт на старый экран, Обзор уже сливает yesterday+overview - дубль.

Слой выборки: поиск, Найти, 7 кнопок оценки, Фильтры, пресеты зон, представления, ⌘K, тема.

Слой Обзора: День/Неделя/Месяц, 7 KPI-плиток, Скачать отчёт, Открыть очередь, Поделиться, хром таблицы дня, МО в PDF.

Слой Найти МО: Нужен разбор, Колонки, сортировка, экспорт, пагинация, 16 select хрома.

Слой разбора: prev/next, PDF, закрыть, вкладки, чипы зон, сохранить решение.

Слой Врачи: Плохие / Хорошие / Все, Открыть случаи.

Не «сломана каждая кнопка». Сломана **модель**: часть кнопок меняет склад, часть - DOM текущей страницы, часть - другой знаменатель. Человек не может предсказать эффект.

### 2.6 Как сейчас устроен поиск МО и анализов

Запрос методиста **не ходит в MariaDB**. Живой путь:

```text
#case-search  →  query()  →  GET /api/methodist/mo/cases
                           →  fact_mo_case (SQLite на GCE PD)
Анализы / Лекарства        →  GET /drugs-labs-kpis
                           →  fact_mo_finding  (+ покрытие из mo_lab.sqlite)
Разбор: панель лаборатории →  mo_lab.sqlite по patient_key + окно дат
```

| Слой | Что ищется | Что не ищется |
|--|--|--|
| Шапка `#case-search` | Подстрока `q` по врачу, короткому Dx, коду МКБ, visit_id в **уже оценённых** строках склада. Саджесты - локальные facets, без API | Текст болезни («гипертон» = 0). Вся МИС. Анализы по названию теста |
| `visit:123` / цифры | `_identity_lookup` в складе, период снимается | Визит, которого нет в `fact_mo_case` |
| Экран Анализы | Коды findings семьи `lab` у клинических МО | Каталог `mis_tests` (глюкоза, СОЭ, …) |
| `mo_lab.sqlite` | Ночной ingest `mis_tests` → значения у пациента | Произвольный поиск теста по всей БД из UI |
| `POST /recompute` | Пересчёт **уже лежащих** дней | «Подтянуть этот визит из МИС» |
| CLI `ingest_mo_visit_from_mis.py` | Один visit_id с GCE в склад | Нет кнопки в кабинете |

Поэтому «поиск по большим БД» сейчас **не реализован**. Склад сентября ~8k оценённых клинических МО; `mis_protocol` ~634k строк. Визит сегодняшнего дня до ночного extract+score в поиске не существует.

Нельзя: LIKE по полю `result` на 634k с Mac или без LIMIT. Список - только индексируемые поля (`visit_id`, `date`, `mis_data.diagnos`, врач, `mis_tests.type_name` / `indicator_name`), полный `result` - только после открытия / ingest.

## 3. Целевой продукт

Один рабочий стол. Два маршрута.

```text
/methodist/mo                  Обзор (зерно = все цифры)
/methodist/mo/cases            Найти МО (склад оценок, тот же query)
/methodist/mo/cases/:visit_id  Разбор на всю страницу
/methodist/mo/mis              Поиск МИС (каталог визитов и анализов, не только оценённые)
```

Шапка **всегда** (как Amazon applied filters + Stripe date):

```text
[ календарь: 19 сен - 19 сен ▾ ]  [ поиск: врач / МКБ / болезнь ]  [ оценка ▾ ]
чипы: Месяц ×   I10 ×   Терапевт ×     Сбросить всё
8062 случаев
```

Таблица без select «Фильтр: ДАТА». Сортировка заголовком = сервер. Клиентский поиск по 50 строкам, если нужен, подписывать «на этой странице», не «Дата».

Разбор: отдельная страница на 100% ширины контента. Список не сжимается в 680 px. Back = список с тем же query. Prev/Next по `caseNavIds`.

### 3.1 Рубрика «Поиск МИС» (визиты и анализы вне склада оценок)

Отдельный пункт меню, не смешивать с «Найти МО».

«Найти МО» = работа с **уже оценёнными** случаями (KPI, очередь, чипы оценки). «Поиск МИС» = каталог источника: любой визит / анализ из больших таблиц МИС, с пометкой, попал ли он в аналитический склад.

Макет (Linear issues + Stripe object search + Apple Health labs):

```text
Поиск МИС
[ визиты | анализы ]     календарь     врач / филиал
[ visit_id или код / название теста ]

строка: дата · врач · краткий Dx · бейдж
  В аналитике  → открыть разбор
  Не разобрано → [ Проанализировать ]
```

После «Проанализировать»: статус «в очереди» → «готово» → бейдж «В аналитике», строка появляется в «Найти МО» и в KPI дня. Не молчаливый ingest без индикатора.

Визуал выдачи (не таблица из 16 колонок):

| Блок | Содержание |
|--|--|
| Шапка хита | Дата, специальность, филиал, бейдж статуса. Без ФИО пациента в списке |
| Спарк визитов пациента | Точки по датам (есть в каталоге / есть оценка). Клик точки = этот визит |
| Анализы | Горизонтальный таймлайн теста: значение vs референс, цвет только из токенов danger/warn/ok. Группы по `type_name` |
| Карточка покрытия | Кольцо «оценено / найдено в МИС за окно» - отдельный знаменатель, не путать с KPI склада |

Не делать: полнотекст по `mis_protocol.result` (634k blob). Поиск только по индексируемым полям: `visit_id`, дата, врач, `mis_data.diagnos`, `mis_tests.indicator_name` / `type_name`. Текст протокола - после открытия или после ingest.

Связанный закрытый план `2026-08-10-mo-visit-patient-id-search-v1.md`: ID-поиск **внутри склада** + CLI ingest. Эта рубрика - UI поверх МИС и кнопка ingest из кабинета.

## 5. Дизайн (визуал)

Токены `mo-tokens.css` остаются. Не новая палитра.

Принципы (Material 3 density + IBM Carbon for data + Linear chrome):

1. **Один акцент на экране.** Шапка выборки. Остальное - таблица или разбор, не оба в 680 px.
2. **Чип > details.** Выбранное всегда видно и снимается крестиком. Нет «Выбрано: 1» без расшифровки.
3. **Дата - первый контрол**, не десятый в панели. Пресеты Вчера / 7 дней / Месяц / период + popover календаря (как Stripe).
4. **Диагноз - combobox**, не 36 option «I84.9 первый к врачу». Ввод кода -> `icd=`. Ввод текста -> саджест МКБ, не `q=` по подстроке склада, пока бэкенд не умеет.
5. **Разбор - страница.** Типографика текста МО как документ (ширина ~720-800 px колонки текста + 360 px «Что не так» + решение), не узкий 320 px обрез.
6. **Обзор:** либо все карточки про день, либо все про выбранное зерно. Смешивать запрещено.
7. Обрезка текста: `Нет оценки` не режется. Чипы `flex-wrap`. На 1280 проверять, не только 1440.

### 5.2 Визуал рубрики «Поиск МИС»

Тот же `mo-tokens.css`. Отдельная страница, не третий donut на Обзоре.

1. **Бейдж статуса** - одна пара: «В аналитике» (ok) / «Не разобрано» (neutral). После ingest - «Оценивается…» (warn), затем ok. Не три слова «проанализировано мо аналитика».
2. **Таймлайн анализов** - как Apple Health / Epic Result Review: ось дат, точка = значение, полоса референса, выброс цветом `--danger`. Группировка по виду теста. Пусто: «за окно тестов нет», не пустой canvas.
3. **Покрытие** - одно кольцо n_оценено / n_найдено_в_МИС. Подпись «это не KPI склада». Клик «не разобрано» фильтрует список.

# Целостность корпуса протоколов

Статус: active
Дата: 2026-09-05
Предшественники: нет (первый разбор конвейера корпуса целиком)

## Контекст

Корпус клинических протоколов - то, ради чего система существует. Если врач
получает цитату из отменённой редакции, всё остальное - скоринг, интерфейс,
безопасность - не имеет значения. Этот разбор проверял конвейер от PDF на сайте
Минздрава до текста, который попадает в ответ врачу.

Замеры сделаны на проде (`protocol-app`, `europe-central2-a`) 2026-09-05.

## Разобранные вопросы и принятые решения

### Дубликаты PDF - оставить как есть

97 групп по содержимому (MD5), 153 лишних пути в манифесте: один протокол
лежит в 2-5 рубриках, потому что так он опубликован на сайте Минздрава.

Это **не дефект**. В выдаче они сворачиваются
`dedupe_retrieval_by_basename(prefer_slugs=...)` (`rag_server.py:6325`), и
именно наличие копии в рубрике врача позволяет предпочесть его специальность
при ранжировании. Удаление копий сломало бы это предпочтение.

Плата - индекс примерно на 27% больше нужного и лишнее место на диске. При
текущих объёмах (137k чанков, 300 МБ) это дешевле, чем усложнять ранжирование.

Решение: **не дедуплицировать**. Пересмотреть, если корпус вырастет в разы.

### Векторный индекс - в проде его нет

`corpus_vector_index/` (980 МБ, 83652 вектора) на проде **отсутствует**.
Проверено: каталога нет, `RAG_GEMINI_EMBED_RERANK=0`, в логах старта ни одного
упоминания.

Из этого следует факт, который стоит называть прямо: **семантического поиска в
проде нет**, retrieval лексический. Локальный индекс - эксперимент, собранный
2026-07-01 из другого состава корпуса: 83652 вектора против 136610 чанков,
sidecar на 111808 идентификаторов, `embedding_model` пустой, а в текущих
чанках эмбеддингов нет вовсе.

Решение: включать семантику **не сейчас**. Чтобы включить, нужно по порядку:
собрать эмбеддинги для всех 136610 чанков (`scripts/build_chunk_embeddings.py`,
только с GCE - Gemini режет по IP), пересобрать индекс, замерить качество
против лексического на eval-наборе, и только тогда решать. Пока не сделано,
локальный индекс не синхронизировать и на прод не возить.

### Манифест происхождения - главный незакрытый пробел

На проде `minzdrav_protocols/_manifest.jsonl` **отсутствует**. Для 406
протоколов, которые получают врачи, нет записи: откуда PDF взят, когда
скачан, какой у него хеш.

Ночной sync это переживает - при отсутствии манифеста он делает `scan-local` и
работает от состояния диска (`night_kp_sync.sh:68-73`). Но два следствия
плохие:

1. На вопрос «какой именно редакцией вы пользовались» ответа нет, кроме имени
   файла. Для МЗ РБ и для разбора спорного случая этого мало.
2. Диф против сайта считается от диска, а не от записи о происхождении, так что
   подмена или порча файла на диске не будет замечена.

Это следующий шаг по корпусу, см. ниже.

### Воспроизводимость сборки

Единой команды пересборки нет. Порядок шагов (проверен по коду, не запускался
целиком):

1. `download_minzdrav_protocols.py` - PDF + `_manifest.jsonl`
2. `python3 -m corpus_pipeline.run_pipeline` - `output/chunks/chunks.jsonl`
3. `scripts/publish_corpus_chunks.py` - публикация в `corpus_chunks_parts`
4. `scripts/build_corpus_path_manifest.py` - манифест путей
5. `scripts/build_protocol_catalog.py` - каталог и `index.csv`
6. `scripts/build_protocol_summaries.py` - карточки протоколов

Осторожно: `split_chunks_jsonl.py` **удаляет все части** и нарезает заново из
`output/chunks/chunks.jsonl`. На проде туда попадает только последний
инкремент, поэтому его запуск заменил бы 136610 чанков на 34157. Для прода
использовать только `publish_corpus_chunks.py`.

## Риски

- **Публикация требует перезапуска.** Манифест читается один раз при старте,
  перезагрузки на ходу нет. Ночной sync перезапускает контейнер сам; при ручной
  публикации это легко забыть, и текст останется невидимым.
- **Ночной инкремент неполный по составу.** `output/chunks/chunks.jsonl`
  содержит только изменённые протоколы. Любой код, который примет его за полный
  корпус, потеряет данные - именно так ведёт себя `split_chunks_jsonl.py`.
- **Переиздание путей не реализовано, и это опаснее, чем кажется.** Если
  Минздрав меняет протокол без смены имени файла, `--add-missing` его не
  подхватит: путь уже есть. Дописать новые чанки отдельной частью тоже нельзя:
  манифест агрегирует по `source_path`, собирает `byte_offsets` со всех частей,
  а `source_part` запоминает только первую
  (`build_corpus_path_manifest.py:63-64,81`). Смещения второй части читались бы
  из файла первой, то есть по неверным позициям.

  Защита `LazyChunkStore._rows_match_entry` (`chunk_store.py:240`) от этого не
  спасает: она проверяет только первую строку с `source_path`. Первые смещения
  берутся из правильной части, проверка проходит, и мусор с чужих позиций
  принимается как текст этого протокола - врач получил бы фрагменты других
  документов под именем нужного.

  Поэтому `publish_corpus_chunks.py` отказывается переиздавать явно. Правильное
  решение - перезапись части целиком; отдельная задача, пока не сделана. 26
  путей на проде уже расходятся по числу чанков между старой и новой нарезкой
  (например 181 против 145), то есть сценарий не гипотетический.

# Найти МО: поиск и фильтры (v1)

Статус: **active**
Дата: 2026-10-17
Окно сверки: 2026-01-01 - 2026-10-16, только `clinical_visit`, склад GCE `mo_analytics.sqlite`.

## Контекст

Поиск по полному ФИО врача на «Найти МО» за «с начала года» возвращает 0. Тот же врач есть в складе: фильтр «Врачи» за то же окно находит его клинические приёмы. Фамилия одним словом тоже находит.

Причина: SQLite `LIKE` не меняет регистр кириллицы. Поиск подставляет три варианта строки: все строчные, заглавная только первая буква всей строки, весь капс. В `dim_doctor` ФИО записано с заглавной у каждого слова. Из 141 врача с пробелом в ФИО полный запрос не совпадает ни у одного. Подсказка в поле поиска подставляет это же ФИО в строку `q`, поэтому выбор подсказки даёт тот же пустой список.

## Сверка фильтров с складом

Один и тот же срез: API `/cases` и SQL. Совпало.

| Фильтр | API | SQL |
|--|--|--|
| Без поиска, клинические приёмы | 56821 | 56821 |
| Фамилия одним словом | 453 | 453 |
| Полное ФИО в поиске | 0 | 453 при варианте с заглавной у каждого слова |
| Фильтр «Врачи», то же ФИО | 453 | 453 |
| МКБ `I10` и поиск `I10` | 1006 | 1006 |

Период «с начала года» в интерфейсе - 2026-01-01 по вчера. Верх склада на момент сверки - 2026-10-16, то есть окно не обрезает этого врача: его последний клинический приём раньше.

## Что не ломаем этой правкой

- Таблица по-прежнему только клинические приёмы. Консультации, диагностика и профосмотры в неё не входят. У этого врача часть строк склада имеет другой `document_kind` и в «Найти МО» не показывается. Это запертый фильтр, не ошибка регистра.
- Имени пациента в складе нет. Поиск ищет врача, диагноз, МКБ и номер визита.
- Ноль «Критично» честный для шкалы записи. Оценку не пересчитываем.

## Шаг

- В варианты `LIKE` добавить строку с заглавной у каждого слова и у части после дефиса.
- Тест: трёхсловное ФИО и ФИО с дефисом находятся и в нижнем регистре запроса, и как в складе.

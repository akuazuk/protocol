## 1. Контекст: какую работу делает человек

Методист за 2-3 минуты должен:

1. Поставить **период** (день / неделя / месяц / свои даты) и сразу видеть тот же `total`.
2. Поставить **диагноз или МКБ**, врача, оценку - одним контролом, с крестиком снять.
3. Открыть случай **на всю страницу**, прочитать МО, записать решение, стрелками листать выборку.
4. Вернуться к списку с теми же фильтрами (браузер Back).

W0-W7 это умеют частично: `overall_grade` и `icd=` уже режут склад. Остальное выглядит как фильтр, но либо режет 50 строк, либо спрятано, либо врёт цифрой.

## 2. Что есть в проде 2026-09-20 (аудит)

Проверено: браузер 1440×900 + API под admin. PHI в этот файл не писать.

### 2.1 API - правда склада

| Запрос | `total` | ms | Смысл |
|--|--|--|--|
| `period=month` | 8062 | 1669 | база сентября |
| `period=custom&date_from=2026-09-18&date_to=2026-09-18` | 458 | 2053 | день работает, если period=custom |
| `period=month&date_from=2026-09-18` | **8062** | 3499 | дата **игнорируется** без custom |
| `period=yesterday` | 253 | 2925 | «вчера» склада (19.09) |
| `icd=I10` | 126 | 1912 | код работает |
| `q=I10` | 126 | 3884 | то же, вдвое медленнее |
| `q=гипертон` | **0** | 3778 | текст диагноза не ищется |
| `diagnosis_code=I10` | **8062** | 3607 | параметр не в Query, как `overall_grade` до W0 |
| `overall_grade=good` | 329 | 4049 | шкала живая, всё ещё Python-скан |
| `queue_only=1&queue_band=critical` | 13 | 6918 | KPI очереди; плитка Обзора при зерне Месяц показывает **0** |

Цель p95 `/cases` page=1 < 1.5 с с W2 **не закрыта**.

### 2.2 Три независимых «фильтра» (корневая причина жалобы)

1. **Склад / URL** - `query()`: period, icd, overall_grade, врач, спец, queue_band. Это единственное, что меняет 8062.
2. **Панель `<details> Фильтры`** - период, сравнение, филиал, спец, врач, статусы CRM, оценка дублем, две кнопки Применить / Отмена / Сбросить. Календарь `#date-from` / `#date-to` **hidden**, пока не выбрать «Произвольный».
3. **Хром таблицы** (`ensureTableChrome`): `<select>` по уникальным значениям **уже загруженных 50 строк**. Подпись «Фильтр: ДАТА» / «Фильтр: ДИАГНОЗ». На page=1 дата только `2026-09-19`. Выбор не меняет `total=8062`, пишет «Показано N из 50». Две колонки с одним aria-label «Диагноз» (текст и зона).

Плюс полоса оценки и поиск в шапке - четвёртый вход в ту же выборку.

Итог для человека: «выбрал дату / диагноз - ничего не случилось с месяцем» - это не баг ощущения, это другая функция, названная тем же словом.

### 2.3 Разбор случая

Канон ui-target §9: широкая панель, шапка + 3 оценки + «Что не так» + текст + решение.

На проде 1440:

- `wideInspector()` = media 1440, панель **680 px** справа, список с `margin-right: 680px`.
- Таблица уезжает вниз, инспектор режет шапку. Это не split view Google Docs и не полный экран Linear.
- Вкладки «Документ / Проверка», блоки История / КП / Назначения / Замечания сразу на первом экране - против §9.11.
- Ниже 1440 - модалка на весь viewport с backdrop, не маршрут. Back браузера не закрывает разбор как страницу.
- Пользователь явно: открытие = **на всю страницу**.

### 2.4 Обзор врёт зерном

Зерно «Месяц» нажато, чип «текущий месяц». Карточки «Получено 310 / Оценено 252» - **рабочий день 19.09**. «Критично в очереди **0**» при API месяца = 13. Полоса оценки и поиск живут на месяце, плитки - на дне. Google Analytics так не смешивает date range и scorecard.

Обрезается: «Нет оцен», чип периода, «Сравнен…».

### 2.5 Карта кнопок (62 видимых на Обзоре 809 px, больше на 1440)

Слой навигации: Обзор, Найти МО, Врачи, Лекарства, Анализы, Ещё, плюс внутри Ещё Период / Очередь / Отчёты / КП / ЛС / Справка. «Период» в Ещё ведёт на старый экран, Обзор уже сливает yesterday+overview - дубль.

Слой выборки: поиск, Найти, 7 кнопок оценки, Фильтры, пресеты зон, представления, ⌘K, тема.

Слой Обзора: День/Неделя/Месяц, 7 KPI-плиток, Скачать отчёт, Открыть очередь, Поделиться, хром таблицы дня, МО в PDF.

Слой Найти МО: Нужен разбор, Колонки, сортировка, экспорт, пагинация, 16 select хрома.

Слой разбора: prev/next, PDF, закрыть, вкладки, чипы зон, сохранить решение.

Слой Врачи: Плохие / Хорошие / Все, Открыть случаи.

Не «сломана каждая кнопка». Сломана **модель**: часть кнопок меняет склад, часть - DOM текущей страницы, часть - другой знаменатель. Человек не может предсказать эффект.

## 3. Целевой продукт

Один рабочий стол. Два маршрута.

```text
/methodist/mo                  Обзор (зерно = все цифры)
/methodist/mo/cases            Найти МО (тот же query)
/methodist/mo/cases/:visit_id  Разбор на всю страницу
```

Шапка **всегда** (как Amazon applied filters + Stripe date):

```text
[ календарь: 19 сен - 19 сен ▾ ]  [ поиск: врач / МКБ / болезнь ]  [ оценка ▾ ]
чипы: Месяц ×   I10 ×   Терапевт ×     Сбросить всё
8062 случаев
```

Таблица без select «Фильтр: ДАТА». Сортировка заголовком = сервер. Клиентский поиск по 50 строкам, если нужен, подписывать «на этой странице», не «Дата».

Разбор: отдельная страница на 100% ширины контента. Список не сжимается в 680 px. Back = список с тем же query. Prev/Next по `caseNavIds`.

## 7. Контракт фильтров

Один `FilterState` = URL.

Обязательные Query (добить то, что UI уже рисует):

- `date_from`, `date_to` действуют **всегда**, не только при `period=custom`. `period` - ярлык пресета.
- `icd` как сейчас.
- Поиск текста диагноза: либо новый `dx_text=` с SQL LIKE по слоту диагноза, либо UI не обещает «болезнь» в placeholder, пока нет индекса. Сейчас placeholder врёт.
- Не принимать `diagnosis_code`, если бэкенд его выкидывает - или объявить Query и фильтровать как `icd`.

Хром таблицы:

- Удалить row `.col-filters` с экранов склада **или** переподключить change -> `query()` (дата -> date_from=date_to=этот день; диагноз -> icd=). Первое проще и честнее (Amazon не ставит 16 select над каждой колонкой выдачи).
- Клиентский «найти на странице» - одно поле, подпись «среди 50 на экране».

Сброс: одна кнопка «Сбросить всё» = дефолт месяца + clinical_visit. Крестик чипа снимает один ключ.

Никакого второго Применить.

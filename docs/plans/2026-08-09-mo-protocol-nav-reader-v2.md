## 1. Диагноз: почему сейчас «не то»

Методист жмёт **Открыть протокол** и получает не «чтение КП», а **карточки коротких выводов**.

### 1.1 Контент - главный дефект

Источник правды на диске уже абзацный (`source_text` / rich_chunks, часто 300-900+ символов на блок).  
Пайплайн **сжимает** его в обрывки:

| Ступень | Лимит сейчас | Эффект |
|--|--|--|
| `protocol_brief` points | `max_text_chars` 520, часто 1 предложение | «Диагностика нарушений целостности…» без контекста |
| `_points_from_chunks` | split по предложениям | один абзац PDF → много коротких пунктов |
| `protocol_source_view` lead | **160** символов (treatment 240) | в accordion виден только первый хвост |
| Summary card exams/drugs | имя поля, не проза | телеграфные ярлыки |
| UI clamp | 6 строк / 420 символов | даже длинное режется |

Итог: **релевантность низкая** (теряется условие/контекст), **размер мелкий** (не абзац).

### 1.2 Макет - второй дефект

| Ограничение | Значение |
|--|--|
| shell | `max-width: 1160px` |
| rail | фиксированные `15rem` съедают колонку |
| chrome | вкладки «Поиск / После приёма» (для МО скрыты `from=mo`, но layout всё ещё «карточка») |
| визуал | частично `mo-tokens`, но не fullscreen-workspace как разбор случая |

Итог: узкая «визитка», не рабочая поверхность методиста.

### 1.3 Что v1 уже закрыл (не трогать зря)

- never-empty cascade brief → source_view  
- `/mo-protocol-viewer.css` route  
- corpus на GCE (`/var/data/protocol_corpus` + mounts)  
- CTA «Открыть протокол» / deep-link `section`/`page`

v2 **не** про «ещё раз починить 404», а про **другую модель чтения**.

## 2. Цель радикальной переделки

Методист за 15 секунд:

1. Видит **полноширинный** экран в языке МО Аналитики (как `case-workspace`: поверхности, кнопки, чипы, muted teal).
2. Читает **абзацы** клинического текста (минимум 2-4 предложения / ≥280 символов), а не обрывки.
3. Слева - **оглавление разделов PDF** (Диагноз / Обследования / Лечение / …), клик скроллит к абзацам.
4. У каждого абзаца - **Оригинал · стр. N** (PDF на якоре).
5. Structured Summary (дозы, «обязательно», red flags) - **аннотации** к абзацу, не замена текста.
6. Поиск внутри протокола подсвечивает абзацы, не ломает поток.

Не цель: LLM-пересказ; заменить PDF; оценивать МО внутри reader.

## 3. Целевой UX (канон)

```text
┌──────────────────────────────── FULL WIDTH ─────────────────────────────────┐
│ Клинический протокол · рубрика · [из текста / карточка]                      │
│ Полное название КП                                                           │
│ [Оригинал PDF]  [Стр. якоря]     поиск в протоколе…                          │
├────────────┬────────────────────────────────────────────────────────────────┤
│ Разделы    │  ## Лечение                                                     │
│ · Диагноз  │  ┌─ абзац 1 (полный) ─────────────────────────── стр. 12 → ┐   │
│ · Обслед.  │  │ … 3-6 предложений клинического текста …                 │   │
│ · Лечение  │  │ чипы: Будесонид · обязательно                            │   │
│ · Наблюд.  │  └──────────────────────────────────────────────────────────┘   │
│            │  ┌─ абзац 2 ──────────────────────────────────── стр. 13 → ┐   │
│            │  └──────────────────────────────────────────────────────────┘   │
└────────────┴────────────────────────────────────────────────────────────────┘
```

Правила UI:

- `max-width: none` (или `min(100%, 1680px)` на ультрашироких); боковые поля как у МО shell.  
- Rail sticky, узкий (≈12rem), на mobile - горизонтальные чипы.  
- Абзац **развёрнут по умолчанию** (не lead 160 + «ещё»).  
- Без doctor chrome при `from=mo` (уже есть); тот же вид из кабинета методиста.  
- Опционально волна 2: правая колонка PDF.js (split view) - не блокер v2.1.

## 4. Новая модель данных: paragraph units

### 4.1 Источник истины (порядок)

```text
L1  rich_chunks (если RAG/файл доступен) - typed + page + entities
L2  protocol_summaries/source_text - sectioned paragraphs
L3  Protocol Summary card - только аннотации (dose, level, severity)
L4  PDF - оригинал по page
```

**Чтение = L1/L2. Карточка = L3 overlays. Не наоборот.**

### 4.2 Контракт API (новый или расширенный)

`GET /api/protocol-reader?path=&q=&section=&page=`

```json
{
  "available": true,
  "title": "…",
  "source": "rich_chunks|source_text",
  "toc": [{"id": "treatment", "label": "Лечение", "count": 12}],
  "paragraphs": [
    {
      "id": "treatment-3",
      "section_id": "treatment",
      "text": "полный абзац ≥280 символов или 2+ предложения",
      "page_start": 12,
      "entities": {"drugs": ["Будесонид"]},
      "annotations": [{"kind": "dose", "label": "200-400 мкг 2 р/сут"}]
    }
  ]
}
```

Правила качества абзаца:

| Правило | Порог |
|--|--|
| минимум символов | **280** (мягкий 180 только если страница короткая) |
| минимум предложений | **2** (или 1, если ≥280 и ends with `.`) |
| запрет mid-sentence start | как сейчас |
| legal/admin / glossary | отбрасывать целиком |
| не резать посередине предложения | clip только по границе предложения |
| max на абзац | ~1200 символов; хвост - «Показать полностью» |
| дедуп | Jaccard по нормализованному тексту |

Legacy `/api/protocol-brief` оставить для «режима на приёме» / совместимости; reader UI **не** строить на brief points.

### 4.3 Где править код

| Файл | Роль в v2 |
|--|--|
| NEW `clinical_knowledge/protocol_reader.py` | сбор paragraphs из L1/L2 + annotations из L3 |
| `protocol_source_view.py` | lead_max убрать из primary path; отдавать полный `text` |
| `protocol_brief.py` | не primary для reader; опционально visit-mode |
| `rag_server.py` | `GET /api/protocol-reader` |
| `proto-viewer.html` → rename UX to reader shell | fullscreen layout |
| `mo-protocol-viewer.css` + `mo-tokens` / паттерны `mo-ui` | full width, detail-block look |
| `mo-app.js` | ссылка та же `/proto-viewer.html?…&from=mo` |

## 6. Метрики

| Метрика | Сейчас (типично) | Цель |
|--|--|--|
| медиана длины блока в primary UI | ≪160-200 | ≥280 |
| доля блоков ≥280 символов | низкая | ≥70% на smoke 20 КП |
| доля блоков с `#page=` | частичная | ≥80% |
| ширина контента | 1160px shell | ≥95% viewport (до 1680) |
| «обрывки / мусор» на smoke | жалобы | 0 критичных |
| время до первого абзаца | - | <2 с после warm cache |

Smoke-набор: 20 КП (астма, ЧЛХ, педиатрия, терапия) из разбора + stomatology.

## 8. Риски

| Риск | Митигация |
|--|--|
| Длинные абзацы = шум legal | жёсткие фильтры на весь блок, не на «первое предложение» |
| RAG chunks=0 на GCE | L2 source_text уже в corpus mount; reader не зависит от RAG warm |
| Первый load summaries медленный | cache reader payload per path (TTL) |
| Конфликт с doctor chrome | `from=mo` shell без вкладок; doctor может подключить тот же reader позже |
| Параллельные PR по `mo-app.js` / viewer | отдельная ветка; не трогать дашборды |

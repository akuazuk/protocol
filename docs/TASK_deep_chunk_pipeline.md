# Задание: Глубокий переразбор всех PDF протоколов в rich-чанки

## Цель

Прочитать **все 478 PDF** из `minzdrav_protocols/`, полностью извлечь текст,
убрать служебные колонтитулы и преамбулы постановлений, разбить на
осмысленные смысловые части, структурировать таблицы и алгоритмы,
пронаковать каждый чанк максимально богатыми метаданными.

Результат — файл `output/rich_chunks/rich_chunks.jsonl`, пригодный для
семантического поиска, анализа КЗ и кросс-протокольного сравнения.

---

## Что убирается (фильтрация «шума»)

| Паттерн | Причина удаления |
|---------|-----------------|
| `ПОСТАНОВЛЕНИЕ МИНИСТЕРСТВА ЗДРАВООХРАНЕНИЯ … Об утверждении…` | Юридическая шапка, не несёт клинической информации |
| `На основании … статьи … Закона …` | Правовая преамбула |
| `ПОСТАНОВЛЯЕТ: 1. Утвердить…` | Шаблонное оперативное поле |
| `Министр …`, подпись / ФИО | Подпись |
| Номера страниц, повторяющиеся колонтитулы | Артефакты PDF |
| Строки `Форма …`, `Приложение № N` в отрыве от содержания | Служебные метки |

Правило: блок удаляется если **все** строки в нём совпадают с шаблонами
выше и блок стоит **до первого** раздела «1.» или «Глава 1» протокола.

## Схема разбиения на чанки

### 1. Уровни иерархии

```
Документ
  └── Раздел (section)          ← "1. Диагностика", "2. Лечение" …
        └── Подраздел (sub)     ← "1.1.", "1.1.1."
              └── Чанк (chunk)  ← абзац / пункт / таблица / алгоритм
```

### 2. Правила нарезки чанков

- **Минимум 80 символов**, максимум **1 200 символов** (мягкий лимит).
- Разрезать по **нумерованным пунктам**: `1.`, `1)`, `п. 1`, `п.п. 1.1`.
- Разрезать по **абзацам** (`\n\n`), если нумерации нет.
- Если абзац > 1 200 символов — разрезать по **концу предложения** (`[.!?]\s`).
- Таблица → один специальный чанк типа `table` (см. ниже).
- Алгоритм / схема → один чанк типа `algorithm`.
- Перечень показаний / противопоказаний → чанк типа `criteria_block`.

### 3. Специальный тип `table`

Каждая таблица конвертируется в **Markdown-таблицу** (`| col | col |`).
Если таблица > 15 строк — делится на части по 15 строк с повтором заголовка.
Дополнительно сохраняется поле `table_caption` — ближайший заголовок выше таблицы.

### 4. Специальный тип `algorithm`

Алгоритм (numbered flow) → структурированный список шагов:
```json
{
  "steps": [
    {"step": 1, "condition": "если …", "action": "назначить …"},
    ...
  ]
}
```

## Метки (labels) для каждого чанка

### Обязательные поля

| Поле | Тип | Описание |
|------|-----|----------|
| `chunk_id` | str | Уникальный ID: `{doc_id}_{sec_idx}_{chunk_idx}` |
| `doc_id` | str | SHA-256[:24] пути файла |
| `source_path` | str | Относительный путь PDF |
| `file_name` | str | Имя файла PDF |
| `specialty_slug` | str | Рубрика (папка) |
| `specialty_ru` | str | Русское название рубрики |
| `chunk_type` | str | Тип чанка (body / table / algorithm / criteria_block / treatment / diagnostics / …) |
| `section_title` | str | Заголовок раздела, в котором находится чанк |
| `section_path` | list[str] | Иерархия разделов от корня |
| `section_number` | str | Номер раздела (`"1"`, `"1.2"`, …) |
| `page_from` | int | Начальная страница (1-based) |
| `page_to` | int | Конечная страница |
| `text` | str | Основной текст чанка (без служебных строк) |
| `embedding_ready_text` | str | `section_title + "\n" + text` для эмбеддинга |

### Сущности (извлекаются автоматически)

| Поле | Тип | Описание |
|------|-----|---------|
| `icd10_codes` | list[str] | Коды МКБ-10 в тексте |
| `icd10_primary` | list[str] | Коды из раздела «шифры МКБ» / «классификация» |
| `population` | list[str] | Группы населения: `взрослые`, `дети`, `новорождённые`, `беременные`, `пожилые` |
| `age_range` | list[str] | Явные возрастные диапазоны: `"0–18 лет"`, `"старше 60 лет"` |
| `sex` | list[str] | `мужчины` / `женщины` — если явно упомянуто |
| `care_setting` | list[str] | `стационар`, `амбулатория`, `скорая помощь` |
| `conditions` | list[str] | Диагнозы / нозологии текстом |
| `drugs` | list[str] | МНН лекарственных средств |
| `procedures` | list[str] | Процедуры и вмешательства |
| `lab_tests` | list[str] | Лабораторные показатели (HbA1c, ПТИ, …) |
| `imaging` | list[str] | Методы визуализации (УЗИ, КТ, МРТ, …) |
| `durations` | list[str] | Сроки лечения / наблюдения |
| `dosages` | list[str] | Дозировки ЛС |
| `severity` | list[str] | Степени тяжести (лёгкая / средняя / тяжёлая) |
| `keywords` | list[str] | Унифицированный список ключевых слов (≥ 4 символа) |

### Метаданные протокола (на уровне файла, повторяются в каждом чанке)

| Поле | Тип | Описание |
|------|-----|---------|
| `protocol_title` | str | Полное название протокола (очищенное) |
| `approval_date` | str | Дата утверждения `YYYY-MM-DD` |
| `approval_number` | str | Номер постановления |
| `approval_body` | str | Орган утверждения |
| `replaces` | list[str] | Перечень отменяемых протоколов (текстом) |
| `related_protocols` | list[str] | Упомянутые КП (кросс-ссылки) |
| `has_tables` | bool | Есть ли таблицы |
| `has_algorithms` | bool | Есть ли алгоритмы/схемы |
| `total_pages` | int | Количество страниц PDF |
| `language` | str | `ru` |

### Флаги качества

| Поле | Тип | Описание |
|------|-----|---------|
| `extraction_confidence` | float | 0–1: 1.0 = хороший текстовый слой, < 0.5 = OCR/сканированный |
| `is_preamble_filtered` | bool | Были ли удалены строки преамбулы |
| `chunk_has_table` | bool | Чанк содержит структурированную таблицу |
| `chunk_is_empty` | bool | Чанк остался пустым после фильтрации |

## Выходные файлы

```
output/
  rich_chunks/
    rich_chunks.jsonl          ← все чанки, один JSON на строку
    _manifest.json             ← статистика: сколько PDF, чанков, таблиц
    _errors.jsonl              ← PDF с ошибками извлечения

    {doc_id}.json              ← полный паспорт каждого файла (все метки)
```

## Алгоритм работы скрипта (высокоуровнево)

```
для каждого PDF в minzdrav_protocols/ (рекурсивно):
  1. extract_pdf()       → raw text, постраничный mapping
  2. filter_preamble()   → убрать шапку постановления
  3. detect_sections()   → разбить на разделы по заголовкам
  4. split_chunks()      → нарезать разделы на чанки (max 1 200 симв.)
  5. extract_tables()    → таблицы → markdown, добавить как отдельные чанки
  6. extract_entities()  → МКБ, популяция, ЛС, возраст, тяжесть …
  7. build_metadata()    → title, approval_date, related_protocols …
  8. write_jsonl()       → дописать в rich_chunks.jsonl
```

Скрипт идемпотентен: если `--resume`, пропускает уже обработанные файлы
(проверяет по `_manifest.json`).

## Примечания к реализации

1. **fitz (PyMuPDF)** доступен в `.venv` — использовать его для PDF.
2. Таблицы извлекать через `page.find_tables()` (API PyMuPDF ≥ 1.23).
3. Если `find_tables()` не находит таблиц — fallback: блоки с `\t` или
   `|` конвертировать в Markdown вручную.
4. Кросс-ссылки на другие протоколы: ищем паттерны типа
   `(КП|клинический протокол)[^.]{5,80}(от|пост|№)`.
5. Возрастные диапазоны: `(\d+)\s*[-–]\s*(\d+)\s*(лет|год|месяц)`.
6. Степени тяжести: `лёгк|средн|тяжёл|крайне тяжёл`.
7. Скрипт выводит прогресс-бар через `print` (один `.` на файл).

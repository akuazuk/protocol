# План: понятные приоритеты МО + хвосты разбора визита 3600047

## Контекст

Разбор визита `3600047` / пациент `254508` (05.08.2026, мигрень, эсциталопрам + суматриптан):

- движок дал **P1** (Major DDI) и статус `review`, overall 60% (risk-cap);
- в UI оставались сырые **P0/P1/P2/P3** и местами P1 красился как `critical` → путаница с «Критично»;
- в Настройках есть потолки балла при P0/P1, но нет ручек «что считать Критично/Важно»;
- ложный DDI `diclofenac + escitalopram` при плане с мелоксикамом - сигнал извлечения ЛС из анамнеза/шума.

Внутренние коды `P0..P3` в JSONL/warehouse/SQL **не меняем** (совместимость). В UI и справке - только русские названия.

### Канон названий (v1)

| Код | UI | Смысл |
|-----|-----|--------|
| P0 | **Критично** | риск вреда / критический дефект; status `critical`, cap overall |
| P1 | **Важно** | клинически важно (Major DDI, safety, сильный дефект) |
| P2 | **Умеренно** | умеренный сигнал (напр. Moderate DDI) |
| P3 | **Оформление** | полнота/форма записи |

## Метрики

| Метрика | Было | Цель |
|---------|------|------|
| Сырой `P0`/`P1` в видимом UI МО | есть (Обзор findings, Безопасность, expert.html, настройки) | 0 в пользовательских строках |
| P1 с CSS `critical` в топе замечаний | да | нет (тон `important`) |
| Подписи severity в «Как оценивать» | P2=документирование путает с P3 | совпадают с каноном выше |
| Ложные DDI из анамнеза (кейс 3600047) | diclofenac без плана | 0 на этом кейсе (фаза B) |

# Внешняя проверка вёрстки через Composio (v1)

Статус: **active**
Дата: 2026-10-18
Родитель: [2026-10-18-mo-accuracy-ux-program-v1.md](2026-10-18-mo-accuracy-ux-program-v1.md)
Волна: G. Не заменяет сверку склада и не смотрит живые осмотры.

## Что выяснилось 2026-10-18

Поиск инструментов Composio нашёл два подходящих контура, оба на мгновенном аккаунте, без отдельного ключа клиники:

- Firecrawl: разрешены `FIRECRAWL_MAP_MULTIPLE_URLS_BASED_ON_OPTIONS`, `FIRECRAWL_SCRAPE`, `FIRECRAWL_SEARCH`.
- Browser Use: разрешены `BROWSER_USE_START_RUN`, `BROWSER_USE_GET_RUN`, `BROWSER_USE_GET_RUN_STATUS`, `BROWSER_USE_LIST_RUN_EVENTS`.

Вызов `FIRECRAWL_SCRAPE` на `https://protocol.kravira.by/methodist/mo` и на `/api/version` не выполнился. Ответ: кошелёк Instant без кредитов, вызовы на паузе. Пополнение: [бюджет Composio](https://dashboard.composio.dev/~/org/connect/team/budget?add-funds=true). Свой аккаунт Firecrawl или Browser Use подключается через `COMPOSIO_MANAGE_CONNECTIONS`, и тогда мгновенный лимит не нужен.

Google Docs, GitHub, Apify и Semrush через Composio активными не были. PR и issues остаются на локальном `gh`. Этот план в Google Doc не копировался.

Сессия поиска инструментов для этого контура: `work`. Следующий вызов мета-инструментов Composio по этой же задаче передаёт `session_id` `work`, пока задача не сменится.

## Почему Composio не читает прод под методистом

Кабинет `https://protocol.kravira.by/methodist/mo` закрыт входом. Удалённый браузер Composio этой сессии не видит. Токен `X-Methodist-Token`, пароль и живой осмотр в задачу Browser Use и в URL Firecrawl не кладутся. Иначе текст пациента уходит третьей стороне вместе с заданием «оцени дизайн».

Точность чисел на проде проверяют два других контура:

- SQL склада на GCE, в отчёт только счётчики;
- браузер Cursor, уже вошедший методист, сценарий волны, без копирования клинического текста в чат и в Composio.

Composio в этой программе отвечает на другой вопрос: понятна ли вёрстка, подписи, пустые состояния, порядок блоков и ширина, когда данные заведомо фальшивые и известные.

## Стенд, который можно отдать наружу

Новая статическая страница фикстуры, не прод и не склад. Имя файла в духе `frontend/web/methodist/mo-layout-fixture.html` плюс маленький скрипт данных `mo-layout-fixture.js`. На прод-меню её нет. Ссылка только локальная или на отдельный preview, который не смотрит в `/var/data`.

В фикстуре пять выдуманных визитов:

| Ключ | Что на экране | Зачем смотрящему |
|---|---|---|
| `fx-major` | Оценка «Важно» до волны F, причина с выдуманной парой «Препарат А + Препарат Б», бейдж Major | Видно ли нарушение без открытия |
| `fx-nsaid` | «Важно», причина «Одновременно два НПВП» | Дубль не спрятан общей фразой |
| `fx-empty-dx` | «Важно», причина про диагноз и МКБ | Диагноз не подменён риском |
| `fx-stale` | «Важно» и метка «оценка старше замечания», замечаний нет | Пустая карточка не выглядит здоровой |
| `fx-critical` | «Критично», красный флаг выдуманного названия | Ноль не единственное состояние чипа |

Плюс отдельные состояния экранов: очередь с нулём критичных и с одним критичным, врач с кнопками оценок, лекарства с двумя ярусами (в оценке / не в оценке), отчёт дня с подписью P0, справка с тремя словами «критично».

Никаких реальных `visit_id`, фамилий, дат рождения, доз из клиники. Текст осмотра - одна фраза «Текст осмотра фикстуры».

Страница повторяет боевые классы `mo-ui.css`, чтобы замечание по отступу имело смысл для прода. Боевой `mo-app.js` на фикстуре не ходит в API: данные зашиты. Иначе preview начнёт тянуть прод.

## Прогон, когда кредиты или свой аккаунт есть

Порядок вызова, без импровизации:

1. `COMPOSIO_SEARCH_TOOLS` с целью «scrape a local or preview fixture page» и «browse a static fixture and list layout problems». Новая сессия, если это уже не продолжение `work`.
2. Убедиться, что у Firecrawl или Browser Use соединение активно. Если нет - ссылка на подключение человеку, ждать, не вызывать инструмент.
3. `COMPOSIO_GET_TOOL_SCHEMAS` для тех slug, у которых в поиске нет полной схемы.
4. `COMPOSIO_MULTI_EXECUTE_TOOL`. На балансе 2 доллара хватает одного прогона: `max_cost_usd` не выше 1, чтобы списание при старте не забрало весь кошелёк. Второе снятие страницы Firecrawl только если после браузера остались деньги. `judge` не включать. Повторный прогон после волны B ждёт нового пополнения, эти 2 доллара его не покрывают.
5. Задача браузеру пишется по-английски и указывает только URL фикстуры. Текст задачи перечисляет вопросы, не просит «найти ошибки врачей».

Вопросы к браузеру, каждый отдельным пунктом отчёта:

- На «Найти МО» у `fx-major` причина содержит оба выдуманных названия, не фразу «Важный сигнал риска».
- Чип «Критично» у `fx-critical` виден, у пустого набора есть объяснение нуля.
- Кнопки врача называются оценками, график зоны подписан как зона.
- На лекарствах взаимодействия не стоят под бейджем «не в общей оценке».
- Карточка `fx-major`: первая фраза проверки совпадает с причиной в списке.
- Карточка `fx-stale`: есть слова про устаревшую оценку.
- На ширине около 390 колонка причины не единственная уехавшая за экран без карточного вида.
- В видимом тексте нет слов «пациент найден» и нет длинной простыни критериев выше первой фразы.

Firecrawl по тому же URL: `formats` = markdown и screenshot, `onlyMainContent` = false, чтобы не выкинуть меню. Скриншот сравнивается с ожиданиями вопросов, не с вкусом модели. Расхождение записывается как пункт волны G: селектор, что ожидали, что видно.

Поиск Firecrawl по чужим статьям про «dashboard UX» в приёмку не входит. Он не знает шкалу №55 и три смысла слова «критично».

## Чего прогон не делает

- Не логинится на `protocol.kravira.by`.
- Не скачивает PDF случая.
- Не нажимает экспорт, печать, пересчёт, «проанализировать».
- Не прикладывает к задаче файл склада, jsonl оценок, выгрузку МИС.
- Не создаёт issue на GitHub через Composio. Замечание возвращается в чат и, если его принимают, становится строкой в документе волны.

## Когда волна G считается пройденной

На текущих 2 долларах волна G - один прогон фикстуры после того, как страница уже собрана локально. Отчёт без персональных данных. Второй прогон после волны B в этот баланс не входит. Волны A-F от этого прогона не зависят: их точность проверяется SQL и браузером Cursor.

## Риски

- Мгновенный Browser Use тарифицируется при старте прогона. Потолок `max_cost_usd` обязателен.
- Фикстура разойдётся с боевым CSS, и отчёт будет про стенд, не про прод. Поэтому фикстура подключает тот же `mo-ui.css`, а не копию.
- Пополнение кошелька организации включает Instant для всех мгновенных приложений, не только для этого аудита. Решение о пополнении принимает владелец бюджета, не агент.

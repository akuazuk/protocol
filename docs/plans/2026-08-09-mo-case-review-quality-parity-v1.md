## 1. Цель

Методист в разборе **любого** МО за 2-3 минуты получает тот же уровень ясности, что в
экспертном разборе `mo_1_test`:

1. **Что по методике** (0 / 0.5 / 1 / н/д) - по зонам и по каждому критерию.  
2. **Что по смыслу клиники** - где жалобы, осмотр, диагноз и план не сходятся.  
3. **Что по МКБ** - есть ли формулировка/код в справочнике (без ложных weak).  
4. **Какой КП** открывать и почему план н/д или штрафуется.  
5. **Что сказать врачу** - 3-6 конкретных пунктов, не сырой список кодов findings.

Не цель: один «магический %» вместо зон; LLM вместо рубрики МЗ; штраф плана без КП.

## 2. Эталон разбора (контракт выхода)

Любой case detail должен уметь собрать объект `case_review_brief` (и отрисовать его).

```text
case_review_brief
├─ header          визит · пациент · дата · врач · спец · Dx/МКБ
├─ zones           оформление / диагноз / план / риск  (band + 1 фраза why)
├─ criteria_table  все критерии методики, сгруппированы по зонам
├─ clinical_gaps   клиника↔диагноз↔план (детерминированно + опц. LLM)
├─ icd_status      ok / нет Dx / не в МКБ / слабо  (+ evidence, без ложных)
├─ protocol        топ-1 КП · статус matched|unmatched · влияние на зону плана
├─ doctor_feedback 3-6 пунктов «что сказать врачу»
└─ confidence      что machine уверенно / что только черновик ИИ
```

### 2.1 Эталонные блоки (как в разборе `mo_1_test`)

| Блок | Пример содержания | Источник истины |
|--|--|--|
| Оценки зон | Оформление слабо 91% (тянет risk_factors 0.5); Диагноз ok; План н/д | `mo_zone_scores` |
| Критерии | Таблица: параметр · 0/0.5/1/н/д · пояснение | `zones.criteria` |
| Клинические разрывы | Жалоба «кашель» vs осмотр «кашля нет»; стопы в Dx?, в осмотре «без отклонений» | concordance + новые правила |
| МКБ | Формулировки в справочнике; не «ближайший ринит 0.38» на мультиDx | name_match + directory |
| КП | Детская БА пост. МЗ 2025 №38; без КП план не штрафуем | protocol_suggest |
| Врачу | Согласовать осмотр с жалобами; уточнить терапию астмы; почистить МКБ/опечатки | synthesizer (см. §5) |

UI: этот brief - **первый экран** правой колонки (после трёх карточек зон).  
Сырые findings / №55 / CRM - ниже, в «Подробнее» / «Служебное» (как в UI-target v2).

## 3. Разрыв: сейчас vs эталон

| Нужно методисту | Сейчас | После плана |
|--|--|--|
| Понятные зоны | есть (PR zones) | без изменений контракта |
| Разбор по критериям | частично (PR #82 brief) | всегда открыт, все критерии, evidence |
| Клиника «не сходится» | точечно (Смирнова shadow); на `mo_1_test` почти нет | пакет правил complaint↔exam↔dx |
| МКБ без ложных weak | ломалось на мультиDx | PR #82 + калибровка |
| КП с нормальным названием | мусор OCR / rehab по J45 | title fallback + ранжирование |
| «Что сказать врачу» | textarea методиста вручную | авто-черновик 3-6 пунктов |
| Связный нарратив | только если LLM-judge на очереди | brief для **всех** clinical_visit дня |

## 4. Архитектура слоёв (не смешивать)

```text
L0  Слоты МО + PDF-текст
L1  Зоны / рубрика МЗ 0·0.5·1          → всегда, primary UI
L2  МКБ справочник (name + code)       → chip + findings
L3  Клиническая согласованность        → findings + clinical_gaps[]
L4  Protocol suggest                   → КП; влияет только на zone2b
L5  Синтез doctor_feedback             → сначала шаблоны из L1-L4
L6  LLM narrative (опционально)        → обогащает L3/L5; не ломает L1
```

Правила:

1. L1 никогда не зависит от LLM.  
2. L3 детерминированный baseline; LLM только добавляет/уточняет.  
3. L4 не ставит балл «плохому плану», если КП `unmatched`.  
4. L6 только GCE (`run_on_gce.sh`), не Mac.  
5. В UI явно: «методика» vs «клиника» vs «черновик ИИ».

## 5. Фазы реализации

### Фаза A - каркас brief в API/UI (P0, 1 PR)

**Сделано частично:** criteria brief в PR #82.  
**Осталось:**

- [ ] Backend: `build_case_review_brief(case_detail) -> dict`  
      (`clinical_knowledge/mo_case_review_brief.py`)
- [ ] Собрать из уже существующих: `zones`, findings (сгруппировать), `protocol_suggest`,
      `icd_visit_status`, history one-liner
- [ ] API case detail: поле `review_brief` (не ломать старый payload)
- [ ] UI: секция «Итог разбора» над «Что не так» - зоны why + criteria + 3-6
      автопунктов из шаблонов (см. фазу B)
- [ ] Фикстура: `mo_1_test` / visit gold → snapshot brief

**Метрика A:** на любом clinical_visit в разборе есть `review_brief` с ≥ zones+criteria.

### Фаза B - doctor_feedback из machine (P0, тот же или следующий PR)

Детерминированный synthesizer (без LLM):

| Сигнал | Пункт врачу (шаблон) |
|--|--|
| criterion score 0 / 0.5 | «Дополнить: {title} - {reason}» |
| finding concordance P0/P1 | текст finding + link к полю |
| `kp_status=unmatched` | «КП не подобран - план не штрафуем; проверьте подбор» |
| `kp_status=matched` + plan 0/0.5 | «Сверить план с КП: {protocol_title}» |
| icd weak/missing | «Уточнить формулировку/код МКБ» |
| prior отсутствует | «Коррекции плана не оценивались (первый контакт)» |

Лимит 6 пунктов; дедуп по смыслу; сортировка: Риск → Диагноз/клиника → Оформление → План.

**Метрика B:** на `mo_1_test` после A+B brief содержит пункты про осмотр/факторы риска/КП н/д
(когда сработают правила фазы C).

### Фаза C - клинические разрывы для «любого МО» (P0/P1)

Расширить concordance beyond Смирнова. Минимум правил для parity с экспертным разбором:

| Код | Условие (черновик) | Пример `mo_1_test` |
|--|--|--|
| `B_complaint_exam_mismatch` | токен жалобы (кашель/насморк/боль/хромота…) и в осмотре явное отрицание той же оси | кашель vs «кашля нет» |
| `B_dx_not_in_exam` | нозология/орган в Dx (стопы, ногти, голова) не отражены в objective | M21.4? при «КОС без отклонений» |
| `B_tentative_dx_weak_support` | Dx с «?» без опор в статусе/обследованиях | E55.0?, G44.2? |
| `B_chronic_dx_therapy_absent` | хронический Dx (астма и др.) в анамнезе/диагнозе и нет текущей терапии/контроля в тексте | БА в ремиссии, терапия не описана |
| `B_risk_mentioned_unscored` | уже закрыто маркерами PR #82; оставить regression-тест | семейная АГ |

Shadow → primary после калибровки на ≥20 кейсах (как ICD name).  
Писать в `clinical_gaps[]` brief и в findings с `linked_fields`.

**Метрика C:** на gold-пакете (`mo_1_test` + Смирнова + 5 смешанных) precision findings ≥ 0.7
при ручной разметке методиста.

### Фаза D - КП в разборе без мусора (P1)

- [ ] Title: boilerplate OCR → filename (часть #82); добить реестр карточек при необходимости
- [ ] Ranking: при детской БА не поднимать rehab/чужие рубрики выше целевого КП  
      (штраф match_kind / audience / title-noise)
- [ ] В brief.protocol: одна строка топ-1 + «ещё N»; при unmatched - явная фраза про н/д плана
- [ ] После matched - пересчёт zone2b видимо в том же разборе (уже есть engine; проверить UX)

**Метрика D:** `mo_1_test` топ-1 = детская БА пост. МЗ 2025 №38 с читаемым title.

### Фаза E - LLM-нарратив на все clinical (P2, не блокирует A-D)

Сейчас LLM-judge только action-очередь. Для parity «как эксперт»:

1. Короткий **case narrative** (JSON):  
   `summary_ru`, `clinical_gaps_ru[]`, `doctor_feedback_ru[]`, `confidence`  
   на базе L1-L4 (модель не выдумывает баллы зон).
2. Запуск: night GCE batch на clinical_visit дня **или** lazy on open case
   (`MO_CASE_NARRATIVE=1`), лимиты и стоимость отдельно.
3. UI: блок «Черновик ИИ» под machine-brief; не перекрывает методику.
4. Primary в overall - только после ≥30 размеченных packs.

Не смешивать с ICD LLM grey-zone и action-judge KPI без явного флага.

**Метрика E:** доля clinical_visit дня с narrative ≥ 80% при включённом batch;
расхождение «ИИ vs machine zones» логируется, не ломает UI.

### Фаза F - калибровка и gold (сквозная)

- [ ] Gold pack: `mo_1_test` + 15 разнообразных МО (педиатрия, терапия, узкие)

- [ ] Eval script: `scripts/eval_mo_case_review_brief.py` - coverage / precision gaps

## 6. UI-спека (правая колонка разбора)

Порядок сверху вниз (заменяет хаос секций):

1. **Три зоны** (как сейчас)  
2. **Итог разбора** (`review_brief`):  
   - «Слабые места методики» (bullet)  
   - «Клиника» (bullet gaps)  
   - «МКБ» (одна строка-статус)  
   - «Протокол» (одна строка)  
   - «Что сказать врачу» (3-6)  
3. **Что не так** - findings с фильтрами зон  
4. **Разбор по критериям** - полная таблица (open)  
5. **История** - одна строка  
6. **Протоколы** - топ-1 + ещё N  
7. **Решение методиста** (collapsed dock)  
8. **Подробнее / Служебное**

Запрет на первом экране: англ. Safety/Overview, двойные KPI LLM, treemap, сырой JSON.

## Контекст

L1 считает **один визит**. Если диагноз/план «плохо», методист должен увидеть:
это новый случай или продолжение уже описанного у этого врача / специальности.

На проде история есть только с 26.07 (есть `patient_key`). Официальный балл
историю не меняет (`MO_PATIENT_HISTORY_IN_PRIMARY=0`). Это правильно: тонкий
сегодняшний визит не становится «хорошим» только потому, что в марте диагноз
уже писали.

---

## Алгоритм (три слоя, не один rescore)

```text
L1 (как сейчас)  →  зоны + whitelist-очередь
        │
        ▼
Слой A. Дешёвая непрерывность (этот PR)
  бандл same_doctor / same_specialty
  тот же stem МКБ или близкий текст Dx
  вердикт: known_episode | new_problem | no_history
        │
        ▼
Слой B. Глубокий прогон истории (очередь, GCE, не Mac)
  только отобранные МО
  читаем слоты прошлых визитов (жалобы / статус / план)
  shadow-пересчёт: не штрафовать хронический анамнез, если он уже есть;
  сегодняшний осмотр и актуальный план всё равно обязательны
        │
        ▼
Слой C. Сильная модель
  только серый хвост слоя B + safety
  Gemini/сильная модель на GCE, не с Mac
```

Официальный `overall_pct` слой A **не трогает**. Слои B/C пишут shadow / пакет
методиста, в SSOT - только по явному решению.

---

## Как отбирать на B/C (сортировка)

Чем выше балл, тем раньше глубокий прогон. Safety всегда впереди.

| Балл | Когда | Зачем |
|--|--|--|
| 200 | `attention=safety` / Critically | риск, история вторична |
| 150 | зона диагноз/план bad\|weak **и** тот же эпизод у врача/спец. | L1 мог наказать продолжение случая |
| 80 | плохие зоны **и** есть prior, но другой код | новый повод у знакомого пациента |
| 40 | плохие зоны, first_contact / нет ключа | сильная модель, не история |
| 10 | только оформление | не жечь дорогой прогон |

Внутри балла: ниже `overall_pct`, свежее дата.

Не брать в B: уже есть deep-pack; только №55; non-clinical.

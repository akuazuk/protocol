## 1. Контекст: что сейчас на экране

Страница `/methodist/mo` → `page-settings` («Настройки и методика»).
В левом меню пункт **скрыт** (`hidden`); открывается через command palette / deep-link.

| Блок | Содержимое сейчас | Проблема |
|--|--|--|
| Сохранённые представления | фильтры + страница | полезно, но вторично |
| Методика на графиках | select v3 / v4 | устарело: API уже отдаёт v4; текст «v4 станет основной после разметки» путает |
| Плотность таблиц | comfortable / compact | ок, оставить |
| Админ-токен | `MO_ADMIN_TOKEN` в sessionStorage | редкий ops; после учёток почти не нужен методисту |
| Как определяется оценка | оси A/B/C/D + risk-gate из `build_scoring_info` | расходится с продуктовой моделью **зон** (Оформление / Диагноз / План / Риск) и №55 |
| Расходы AI | таблицы night LLM / action-judge | полезно lead/admin; тяжело и «не про разбор» для обычного методиста |

Итог для методиста: экран смешивает **личные prefs**, **устаревшую методику**, **ops-админку** и **биллинг LLM**.

---

## 2. Цель

Один понятный экран «Справка и настройки»:

1. Как мы оцениваем (зоны + кратко №55) - актуальными словами.
2. Личные настройки интерфейса (плотность; представления).
3. Сессия и версия сборки - без AI-биллинга и без переключателя v3/v4.

Не делать из Настроек второй BI и не дублировать вкладку учёток из кабинета методиста.

---

## 3. Решение владельца (зафиксировано 2026-08-09)

1. Ссылка внизу сайдбара: **«Справка»**.
2. Блок AI-расходов: **не показывать**.
3. Переключатель v3/v4: **удалить** (API остаётся на `v4` без UI).

## 4. Целевая структура экрана

```text
Справка и настройки
├─ Сессия
│    кто вошёл · доступ · отчёты с даты · [Выйти] · ссылка на учётки (если methodist token)
├─ Как мы смотрим запись
│    Оформление · Диагноз · План по протоколу · Риск
│    + коротко про №55 и МКБ-чип
├─ Интерфейс
│    плотность таблиц
├─ Сохранённые представления
└─ О системе
     BUILD_VERSION · freshness
```

Навигация: **не** поднимать «Настройки» в основные 6 пунктов; внизу сайдбара - «Справка».

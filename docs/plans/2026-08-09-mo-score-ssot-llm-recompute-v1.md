## 2. Корневые причины (не «сервер сломался»)

### 2.1 Два (и больше) контура «качества / №55»

```text
ТАБЛИЦА  → fact_mo_case.reg55_section_pct          (section pack, 0/0.5/1)
           fallback: fact_mo_score_axis.regulatory (часто другой %)

РАЗБОР   → hero: compute_mo_zone_scores / mo_rubric_mz   (НЕ №55)
           «Балл №55»: attach_reg55_section_to_detail (live)
           axes.regulatory из warehouse может остаться 77.8
           finding D_reg55_gap из measures (score < 1)
```

План `mo-reg55-section-pack-v1` уже требует один контур; в проде таблица и ось D / hero ещё не выровнены.

### 2.2 «Невыполненные» при высоком %

В `evaluate_reg55_section` в `measures` попадает любой applicable с **`score < 1`** (включая **0.5**).
Finding `D_reg55_gap` склеивает их в одну фразу с заголовком «Невыполненные…».

Итог: при 83% (два пункта 0.5 или 0) UI орёт «не выполнено лечение / наблюдение», хотя по Инструкции это **частично / недостатки**, а band уже `compliant_min` (≥80).

### 2.3 МКБ: ложное «слабо согласуется»

`B_icd_dir_text_mismatch` срабатывает при:
- код **есть** и есть в справочнике;
- текст диагноза есть;
- `text_rubric_fit < 0.25`.

Это **не** правило «плохо только без МКБ и без Dx».
Для `3643940` Z00.8 vs «Артериальная гипертензия» - осмысленный сигнал **несоответствия кода клинике**, но формулировка «слабо согласуется с рубрикой» читается как ошибка оформления при валидном коде.
Канон владельца (зафиксировать):

| Ситуация | Вердикт |
|--|--|
| Нет МКБ **и** нет текста Dx | дефект |
| Есть текст Dx, нет кода | **ok** (`icd-absent-ok`) |
| Код есть, в справочнике, текст клиники про другое заболевание | отдельный тип: «код МКБ не соответствует клинике» (осторожно; не путать с опечаткой) |
| Код «выдуман» / нет в справочнике | дефект (редко) |
| Код ок, текст близок к рубрике | ok; **не** слать `B_icd_dir_text_mismatch` |

### 2.4 Live vs warehouse

При открытии случая API может **пересчитать** №55/зоны с другим набором полей, чем publish.
Неполный clinical payload → обвал % (локальный эксперимент: 12.5% без текста).
Таблица остаётся на snapshot склада.

## 4. Целевой канон (SSOT)

```text
Publish / recompute_mo_days (единственный writer)
  case + clinical + block_scores
    → evaluate_reg55_section  → reg55_section_pct, band, pack, weak_points, criteria
    → axes.regulatory := reg55_section_pct   # то же число
    → findings: D_reg55_section_<point> только для score==0;
                D_reg55_section_partial_<point> для score==0.5 (P2, мягкий язык)
    → zones / rubric отдельно, подписи «Оформление / Диагноз / План»

Таблица / очередь / месяц
  читать только fact_mo_case.reg55_*  (без fallback на чужой axis без band)

Разбор случая
  по умолчанию: warehouse snapshot №55 + criteria
  кнопка «Пересчитать сейчас» → тот же evaluate_reg55_section → write-through
  hero = zones (другая метрика)
```

LLM (только GCE `run_on_gce.sh`):
- judge / narrative / ICD grey-zone при спорном `text_rubric_fit` или score 0.5;
- **не** меняет `reg55_section_pct` без флага primary после gold;
- результат в shadow или doctor_feedback, пока не калиброван.

## 1. Зачем

Методист открывает случай, чтобы за 30-60 секунд ответить:

1. Эта запись **хорошая / слабая / плохая / критичная** и почему.
2. Если найден КП МЗ - **план и диагноз сверены с этим протоколом**, а не с общим ощущением полноты текста.
3. Если у пациента есть история, анализы, лекарства - они **вошли в оценку** или честно помечены как «не входили, вот почему».
4. №55 - не спрятанный процент, а **какие пункты разд. V** не выполнены.
5. Что сказать врачу - одним абзацем, без семи разных «итогов».

Сейчас человек видит три зоны, но доказательства (КП, история, лаб, ЛС, №55) лежат в `<details> Подробнее`. Итог выглядит как оценка, а сверка с протоколом часто ещё не подгрузилась или ушла в shadow.

### 2.3 Как сейчас устроена сверка с КП

Канон методики §2.1: «соответствие КП» только для строк 8-13, и только если диагноз есть **и** подобран применимый КП с достаточным trust. Иначе критерий = n/a / ceiling weak, **не** «0% не по протоколу».

Факт кода:

1. `case_protocol_suggest_v5` ищет КП по Dx → МКБ → клинике. Это **подбор документа**, не проверка требований.
2. `resolve_plan_route`: clinical hit с trust A/B → `kp_grounded`, иначе `llm_no_kp`.
3. UI зоны 2b не показывает `kp_status` крупно (только мелкая строка в assessment strip и `zoneBandChip`).
4. Карточки КП в корпусе (`protocol_cards.jsonl`) уже содержат exams/treatment/follow-up - **на экране разбора они не разложены** напротив текста плана.
5. Без КП план **нельзя** штрафовать за несоответствие протоколу - это уже написано. Нужно, чтобы при **наличии** КП штраф/зачёт был **по пунктам протокола**, а не по длине поля «Рекомендации».

### 2.4 История, анализы, лекарства, №55

**История.** Бандл `patient_key` + окно as-of даты визита. UI: «к врачу N · к спец N · всего N». Коррекции 2c оцениваются только при prior того же эпизода. Список визитов спрятан. Нет таймлайна диагнозов/планов.

**Анализы.** `fact_mo_lab` по `patient_key`, окно визит−14д…+1д. Reconcile: есть в складе / не указаны в МО / назначены / после визита. Значения без референса. В primary score не входят. Finding «анализы есть, в МО не указаны» - опциональный P3.

**Лекарства.** Нормализация INN, DDInter, high-alert, STOPP, формуляр - как findings семьи `drug`. Карточки `medication_normative_cards`: препарат, доза, ссылки Rceth / КП / pack №55, поле `protocol_check` = evaluated|not_evaluated **без расшифровки**. Реестр Rceth качается на GCE (`2026-08-14-rceth-drug-labels-mo-v1.md`); в разборе это ещё не рабочий label-check 4.1/4.3.

**№55.** `evaluate_reg55_section`: pack по диагнозу/возрасту, пункты 0/0.5/1, pct п.12, band п.13. В UI - процент и таблица глубоко в служебном. Методист не видит, что overall «слабо» из-за fail конкретного пункта разд. V.

### 2.5 Дизайн: что ломает ощущение «современный продукт»

- Две вкладки вместо split view на широком экране.
- Вложенные `<details>` три уровня.
- Одинаковый визуальный вес у зоны, LLM-черновика и CRM.
- Нет «spine» доказательств: клик по «план плохо» не скроллит к пунктам КП и назначениям.
- Текст МО узкой колонкой на «Документ», оценка на другой вкладке - нельзя ткнуть в цитату.
- Карточки препаратов с бейджем «черновик» подрывают доверие даже когда Rceth найден.
- Пустые состояния честные по смыслу («нет prior»), но выглядят как заглушки, не как клинический факт.

## 3. Целевой контракт оценки (не меняем методику, делаем её видимой)

Официальный вердикт случая остаётся таблицей владельца:

```
Оформление (№127)     критерии 1-7      КП не участвует
Диагноз               критерий 8        КП + клиника + МКБ
План по протоколу     критерии 9-13     КП обязателен; 11-12 ещё история
Риск                  DDI / red flag    не %
№55 разд. V           pack пунктов      отдельная градация п.12-13, не hero-%
```

### 3.1 Когда что имеет право менять зону

| Вход | Оформление | Диагноз | План | Риск |
|--|--|--|--|--|
| Текст МО (слоты) | да | да | да | да |
| Подобранный КП (trust A/B) | нет | да, классификации/объём Dx | да, exams/treat/follow-up | нет как % |
| КП не подобран | нет | не писать «не по КП» | n/a / «протокол не подобран», не 0% | - |
| История того же эпизода | нет | контекст | да, коррекции 11-12 | нет |
| Лаб в окне, доступна до визита | нет (кроме «данные обследований» если принесены) | да, опора Dx если результат мог быть известен | да, если КП требует исследование | нет |
| Лаб после cutoff / без времени | нет | не штраф | не штраф, показать как контекст | нет |
| Назначение ∩ инструкция Rceth | нет | нет | да, если КП задаёт схему; иначе контекст | да, противопоказание / high-alert |
| Назначение ∩ КП (схема) | нет | нет | да | нет |
| №55 pack | отдельно; пересечение с 1-13 только как evidence helper №127 | не подменяет 2a | не подменяет 2b | нет |

Запрещено в том же PR, что UI: менять пороги night LLM, SSOT №55, `MO_LAB_IN_PRIMARY` без отдельного решения владельца. Сначала **показать** вклад лаб/ЛС в разборе как доказательство. Включать в primary - отдельная волна R4b/R5b после калибровки.

### 3.2 Один объект `case_review` для экрана

API detail уже отдаёт куски. Экран должен собирать **один документ**:

```text
verdict        overall_grade + 3 зоны + risk
protocol       hit | unmatched | not_applicable  + title + trust + viewer
evidence.dx    клиника ↔ Dx ↔ МКБ ↔ (лаб, если опора)
evidence.plan  пункты КП: есть в МО / нет / вне протокола
evidence.hist  эпизод, prior, что уже описано, коррекция да/нет
evidence.lab   таймлайн + reconcile + какие пункты плана/Dx затронуты
evidence.meds  INN, доза, КП-схема, Rceth 4.1/4.3, DDI
evidence.reg55 пункты pack: pass/partial/fail/na + цитата
findings       только то, что в официальной оценке; shadow отдельно
why_ru         2-4 предложения, собранные из зон, не из LLM
```

LLM judge / shadow / brief - вкладка или details «Черновик модели», заголовок: «не меняет оценку склада».

### 4.2 Вердикт

Три карточки как сейчас, но:

- центр/слово шкалы: в норме / слабо / плохо / нет данных;
- для плана без КП: четвёртое состояние **протокол не подобран** (уже в каноне, сейчас легко перепутать со «слабо»);
- клик по карточке открывает соответствующий аккордеон и скроллит документ к слоту;
- overall chip один, причина `reason_ru` рядом, не второй набор процентов.

### 4.3 Блок «Протокол»

Всегда на первом экране, одна полоса:

- найден: короткое название, кнопка «Открыть протокол» (viewer с page/section), мета «подобрано по диагнозу / по МКБ», trust;
- не найден: фраза канона про отсутствие штрафа;
- «ещё N» - остальные кандидаты, оценка релевантности методистом как сейчас.

Под полосой, только если hit A/B: **таблица сверки плана** (волна R2), не список score suggest.

### 4.4 «Почему так»

Машинный `why_ru` из официальных зон (уже есть куски в `review_brief` и `zones.criteria`). Собрать 2-4 предложения:

- «Диагноз слабо: МКБ не из слота / нет опоры в осмотре»;
- «План плохо: в КП требуются X, в рекомендациях нет»;
- «Оформление в норме»;
- «№55: не выполнен пункт …» только если pack fail тянет градацию.

Не подставлять LLM summary в этот блок.

### 4.5 Доказательства по рубрикам

Каждая секция - карточка с статусом `вошло в оценку` / `контекст` / `нет данных`.

**План ↔ КП.** Строки из карточки протокола (обследование, лечение, кратность). Колонки: требование КП · в МО · статус (есть / нет / иначе / не требуется). Источник - `protocol_cards` + `mo_plan_protocol_score.missing_required` / `off_protocol`. Пусто без КП.

**Диагноз ↔ клиника.** Три оси, которые уже считает brief (методика, МКБ, опора), плюс лаб-опора если результат был доступен до визита. Подсветка слотов.

**Назначения.** Одна строка на INN: доза · КП (схема да/нет/нет в КП) · Rceth (показание 4.1, противопоказание 4.3, нет инструкции) · DDI. Бейдж «черновик» только если нет ни КП, ни label. Если label есть - убрать «черновик», написать «по инструкции реестра, ред. ДАТА».

**История.** Таймлайн визитов эпизода (дата, Dx short, тот же врач?). Сводка: first contact / продолжение / коррекция оценивается. Раскрытие слотов прошлого визита. Без ФИО пациента.

**Анализы.** Таймлайн показателя (значение, референс если есть, иначе честно «референса в складе нет»). Reconcile сверху двумя строками. Связь: «глюкоза не упомянута в обследованиях» якорит finding. Не подменять графу exam_data.

**№55.** Не средний % как hero. Список применимых пунктов pack: статус, 0/0.5/1, «что не так», цитата. Сверху градация п.13 словами. Подпись pack. №127 только как «опора», не второй балл.

### 4.6 «Что не так» и решение

Findings только `is_shadow=0`, фильтр по зоне. Клик «показать в тексте» работает в соседней колонке, без смены вкладки на 1440.

Решение методиста sticky справа внизу: три вердикта + комментарий + статус + Сохранить. CRM/обучение в «Дополнительно».

### 4.7 Пустые состояния (не врать)

| Ситуация | Текст |
|--|--|
| КП нет | протокол не подобран - план не штрафуем за несоответствие протоколу |
| Истории нет | нет предыдущего визита того же эпизода - коррекции плана не оцениваются |
| Лаб нет в окне | за 14 дней до визита анализов на складе нет - это не ошибка блока |
| Лаб есть, референса нет | значения показаны, сравнение с нормой недоступно |
| Rceth нет на INN | инструкции в скачанном реестре нет - проверка по КП и DDI |
| Не клинический приём | оценка зон не применяется |

### 4.8 Визуал и a11y

- Сетка: документ `minmax(0, 1fr)`, рельс `380-420px`, gap из `--space-*`.
- Карточки зон: те же `--good/--warn/--bad`, что на Обзоре.
- Таймлайн лаб: линия + точки, выброс `--danger`, tooltip дата/значение/единица, без PHI шире нужного.
- Фокус-кольцо `--focus`, не полагаться только на цвет статуса.
- Тёмная тема: те же токены.
- 720: рельс сверху, документ ниже, без горизонтального скролла (канон E22).

## 1. Контекст

Экран **«Разбор случая»** уже fullscreen (`case-workspace`), слева текст МО,
справа LLM + findings + «Решение методиста». Сейчас неудобно:

| Проблема | Как есть |
|--|--|
| Прокрутка | Весь `drawer-body` скроллится целиком; sticky висит на **форме решения**, а не на тексте МО |
| Форма решения | Три поля `%` (Полнота / Диагноз / Рек.) почти не используются; textarea «Развёрнутый разбор» мала (`rows=6`, max 4000) |
| Язык UI | В разборе мешаются RU и EN: `shadow`, `Follow-up`, `n/a`, `conf A/B`, `model`, `engine`, `gold`, `outcome` (`ok`/`contradiction`), badge `этап A/B` |
| Таблицы дня | «Все случаи» - пагинация по 50; клик по колонкам не сортирует; день из «Отчёты»/«Вчера» не даёт полный табличный срез с теми же фильтрами |
| Полезность | Нет быстрого «следующий в очереди», нет шаблонов разбора, нет явной связки finding ↔ поле МО при сохранении |

Пользовательский запрос (суть):

1. Закрепить **МО слева** при прокрутке; **справа** прокручивать разбор.
2. В «Решение методиста» **увеличить** «Развёрнутый разбор», **убрать** поля Полнота % / Диагноз % / Рек. %.
3. Всё писать **по-русски**.
4. Таблицы заполнены; **за каждый день** - полная таблица с фильтрами и сортировками.
5. Улучшить дизайн и полезность (предложения ниже).

## 2. Цель и метрики

| Метрика | Было | Цель v1 |
|--|--|--|
| Sticky при разборе | форма решения | **левая колонка = текст МО** закреплена в viewport |
| Правая колонка | скролл вместе с МО | независимый scroll (LLM, findings, решение, история) |
| Поля `%` в решении | 3 number input | **удалены из UI**; API принимает `null`/отсутствие |
| Textarea разбора | ~6 строк / 4000 | **≥12 строк**, max **12000**, визуально доминирует в панели |
| EN-лейблы в drawer | ≥10 мест | **0 видимых EN** (кроме кодов МКБ / ID) |
| Таблица за день | косвенно через период | режим **«День YYYY-MM-DD»**: все кейсы дня, фильтры + sort по клику на th |
| Пустые ячейки ID/филиал/врач | бывают `-` | заполнены из secure/warehouse (уже чинили; smoke после) |

## 3. Макет workspace (главное UX)

```text
┌─ header: Разбор случая · визит · пациент · врач · [← очередь] [→] [×] ─┐
│ ┌─ МО (sticky / own scroll) ──────┐  ┌─ Разбор (scroll) ─────────────┐ │
│ │ Жалобы / Анамнез / Осмотр /    │  │ LLM: 3 вопроса (RU)           │ │
│ │ Диагноз / Рекомендации         │  │ Findings + решения по кодам   │ │
│ │ подсветка linked fields        │  │ Решение методиста             │ │
│ │ (details) оценка / оси / МЗ    │  │   вердикты agree/…            │ │
│ │                                │  │   ★ Развёрнутый разбор (big)  │ │
│ │                                │  │   статус / assignee / tags    │ │
│ │                                │  │ История пакетов + CRM         │ │
│ └────────────────────────────────┘  └───────────────────────────────┘ │
└────────────────────────────────────────────────────────────────────────┘
```

### Поведение scroll

- `drawer-body` → `display:flex; height: calc(100vh - header); overflow:hidden`.
- `.case-workspace-clinical`: `position: sticky` **или** отдельный `overflow:auto` на высоту колонки
  (предпочтительно **два независимых scroll-pane**, чтобы длинный МО тоже читался без уезда формы).
- `.case-workspace-decision`: `overflow:auto; height:100%`.
- На узких экранах (`<960px`): колонки стеком; сверху МО (collapse/expand), снизу разбор.
- Убрать текущий `sticky` с `.methodist-decision-panel` (он мешает новому сценарию).

### Навигация в очереди (новое, полезность)

В header drawer:

- «Предыдущий / Следующий» по текущей таблице (очередь или день).
- Горячие клавиши `j` / `k` (опционально, если не в textarea).

## 4. Решение методиста - форма

### Убрать из UI

- `Полнота %` (`#drawer-score-c`)
- `Диагноз %` (`#drawer-score-d`)
- `Рек. %` (`#drawer-score-r`)
- подпись «Корректировка % (shadow, необязательно)»

Backend: `corrected_scores` в review-pack **не обязателен**; при save не слать или слать `null`.
Старые пакеты с scores продолжают читаться, в форме не показываем.

### Оставить / усилить

| Поле | Изменение |
|--|--|
| Вердикты Полнота / Диагноз / Рекомендации | оставить (agree/partial/disagree), подписи строго RU |
| **Развёрнутый разбор** | `rows=14` (или flex-grow), `maxlength=12000`, min-height ~220px, placeholder с чеклистом |
| Статус, ответственный, срок, метки | компактная сетка 2×2 над textarea |
| gold / обучение | чекбокс «Можно использовать для обучения» (вместо «gold») |
| Кнопки | «Сохранить пакет» primary; «МО в PDF»; убрать/переименовать «Анализ документа» если путает |

### Шаблон placeholder (RU)

```text
1) С чем согласен / не согласен по полноте
2) Диагноз: подтверждён / сомнителен - почему
3) План: что добавить / убрать
4) Что сказать врачу (1-2 предложения)
```

### Предложения «полезности» (в v1, если уложимся)

1. **Быстрые фразы** под textarea: чипы «Ложное срабатывание», «Не хватает осмотра»,
   «Диагноз не обоснован», «План неполный» → дописывают в текст.
2. **Счётчик символов** и предупреждение «короткий разбор» при <80 символах перед save
   (не блок, а confirm).
3. В истории пакетов показывать RU-лейблы вердиктов, не raw `agree`.

## 6. Полная таблица за каждый день + фильтры + сортировки

### Продуктовая модель

Единый режим таблицы случаев с явным **днём**:

- Из **Отчёты** / **Вчера**: клик по дню → `period=custom&date_from=D&date_to=D` + страница «Все случаи»
  (или новая вкладка «Таблица дня», если так чище).
- Показывать заголовок: «Все случаи за 2026-08-04 · N записей».
- Фильтры (уже есть multi-select): специальность, филиал, врач, тип документа, статус, поиск `q`.
- Сортировка:
  - клик по заголовку колонки (date, overall, doctor, specialty, filial, status, priority);
  - индикатор ↑/↓;
  - сохранить совместимость с `#sort-by` / `#sort-dir`.
- Пагинация: оставить, но поднять default `page_size` до **100** для дневного режима;
  опция «Показать все за день» если N ≤ 500 (один запрос).
- Пустые ячейки: не `-` молча - показывать «не указан» только если поля реально нет;
  smoke на августовских днях после warehouse repair.

### Очередь разбора

Та же сортировка по клику на th; фильтры периода/дня работают так же
(`queue_only=1` + date range).

### Backend (если не хватает)

В `build_cases` / API проверить whitelist `sort_by`:
`date | overall | priority | doctor | specialty | filial | status | visit_id`.
Сейчас UI шлёт часть полей - добить недостающие на сервере.

## 7. Дизайн (в рамках текущего MO design system)

Без новой «фиолетовой» темы; опираемся на `mo-ui.css`:

- Две колонки с чёткой вертикальной границей (`border-left` у правой).

- Правая колонка: LLM-блок компактнее KPI; решение - «карточка действия» с большим textarea.
- Моушен: только плавный scroll-into-view на linked field (уже есть).

## 9. Риски

| Старые review-pack со `corrected_scores` | читать ok, UI не показывает |

## 10. Definition of Done

1. В разборе при прокрутке текст МО остаётся в левой колонке; правая крутится отдельно.
2. В решении нет полей `%`; «Развёрнутый разбор» крупный и удобный.
3. В drawer нет пользовательских EN-ярлыков.
4. Из отчёта за день открывается полная таблица дня с фильтрами и сортировкой по колонкам.
5. methodist + expert UI ведут себя одинаково.
6. Версия в `/api/version` обновлена, PR в main.

---

## 11. Что сознательно не входит в v1

- Редактирование текста МО / правка МИС.
- Повторный вызов LLM из UI.
- Новые % корректировки (удаляем, не заменяем слайдерами).
- Полный corpus LLM на все кейсы дня (остаётся night queue + action-judge).

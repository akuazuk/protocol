# МО Аналитика: одно слово - одно число (v1)

Статус: **active**
Дата: 2026-10-17
Владелец: методист / руководитель качества
Снято с прода `https://protocol.kravira.by/methodist/mo`, версия `2026-09-27-190453Z-review-steps-flag`, окно 2026-10-01 - 2026-10-16, 6687 клинических приёмов.

Шкалу оценок и склад этот план не пересчитывает. Меняется то, что человек видит и куда ведёт клик.

## Что уже не сходится

| Место | Что написано | Что внутри | Октябрь 2026 |
|--|--|--|--|
| Чип «Критично» | оценка записи | `overall_grade=critical` | 0 |
| Сводка «Найти МО» | та же шкала | good 1920, fair 2438, poor 2239, important 90, critical 0 | сходится с чипом |
| Плитка «Критично в очереди» | замечание в очереди | `queue_critical` | 10 |
| Плитка «Важно в очереди» | то же | `queue_important` | 75 |
| «Нужен разбор» | сумма двух плиток | 10 + 75 | 85 |
| Дневная карточка «крит.» | записи с P0 | `summary.critical` = число визитов с p0 | 29 за 16 октября |

Кольцо «План по протоколу» при доле без КП >= 50% подменяло крупную цифру на долю «без КП» (64% = 4271 / 6687). Рядом у оформления и диагноза крупная цифра - доля «хорошо».

## Шаги

Каждый шаг - отдельный PR, merge в `origin/main`, деплой GCE, проверка на `protocol.kravira.by`.

### Шаг 1. Честные подписи (этот PR)

Сделано в ветке `cursor/mo-analytics-trust-agent1-pc1`.

- Кольцо плана: центр остаётся «% хорошо» среди сравнённых. Подпись: «без сравнения с КП: N из M» и «плохо среди сравнённых: N».
- Плитка «План плохо» показывает и процент плохо, и сколько не сравнивалось.
- Чипы подписаны «Оценка записи». Пустой список по чипу говорит, что это не очередь замечаний.
- Счётчик «Фильтры. Выбрано» не считает запертый клинический приём.
- Второй ряд «День / Неделя / Месяц» на Обзоре снят. Период только в шапке.
- «Таблица дня» и «Полнота за день» переименованы в окно шапки.
- Очередь: убрана фраза «Таблица 40 px». Текст: замечание критично или важно, не оценка записи.
- Отчёты: «крит.» заменено на «с критичным замечанием». Клик ведёт на «Обзор», не на «Вчера».

Проверка на проде после деплоя:

1. Обзор, месяц: у плана крупная цифра с подписью «хорошо», рядом строка «без сравнения с КП».
2. Чип «Критично» на «Найти МО» даёт 0 и пояснение, не молчаливую пустоту.
3. Плитка «Критично в очереди» по-прежнему открывает очередь.
4. В шапке один ряд периода. «Фильтры» без лишней единицы, если выбран только клинический приём.
5. Очередь без «40 px». Карточка отчёта без сокращения «крит.».

### Шаг 2. Шапка

- Поля «С даты» и «По дату» видны только для произвольного периода. Для вчера / 7 дней / месяца / года диапазон остаётся в чипе.
- Кнопка «Произвольный» рядом с пресетами, чтобы даты не пропали без входа.
- Один «Сбросить всё».
- Галочка филиала, специальности и врача применяется сразу. Внутренней «Применить» нет.
- Запертый «только клинические приёмы» - одна строка в панели, без чипа.

### Шаг 3. Найти МО

- Пока едет сеть, старые строки остаются, сверху тонкая полоса. Пустая таблица только если сервер вернул 0.
- В строке кнопка «Открыть», не только клик по `<tr>`.
- Цель первой страницы: меньше 3 с на тёплом складе. Сейчас около 12 с.

### Шаг 4. Очередь = плитка

- Экран «Очередь» по умолчанию - те же случаи, что «Критично в очереди» + «Важно в очереди» (85 в октябре).
- Статусы CRM (назначить, подтвердить, закрыть) свёрнуты, пока ими не пользуются.
- Подзаголовок не обещает CRM.

### Шаг 5. Лекарства и анализы

- Первыми плитками: взаимодействия и дубли групп.
- «Доза / инструкция» (66%) и «Не по протоколу» (0) уходят со первого ряда или подписываются «сигнал, не дефект».
- На Обзоре полоса «черновик» не ставит процент, который не равен примеру под ним.
- Заголовок экрана совпадает с пунктом меню.

### Шаг 6. Служба

- «Поиск МИС» в группу «Служба». В «Работе» остаются Обзор, Найти МО, Пациент, Врачи, Лекарства, Анализы, Очередь.
- На протоколах и инструкциях явная строка, если сверка старше 7 дней (сейчас протоколы 2026-09-26, инструкции 2026-08-18).
- «Ошибок 0» не стоит рядом с «нужно человеку: 1980» без этой оговорки.

### Шаг 7. Справка

- Текст четырёх зон остаётся.
- Кнопки пересчёта склада уходят с этой страницы на действие администратора с подтверждением. Этот шаг не запускает пересчёт.

### Шаг 8. Скачок оформления

- Если доля «хорошо» по оформлению меняется больше чем на 10 п.п. к прошлому окну, под кольцом строка «скачок к прошлому окну, проверьте, не менялась ли методика».
- Саму методику этот шаг не меняет.

## Вне шагов

- Не пересчитывать `overall_grade`, чтобы «Критично» перестало быть нулём. Ноль честный для шкалы записи.
- Не деплоить с грязного `main` и не пушить в `main` напрямую.
- Прод только GCE, `deploy/gcp-app/deploy_to_gce.sh`, после merge, когда `HEAD == origin/main`.

# МО Аналитика: целевой интерфейс v2 (только нужное)

Статус: **active** (канон экранов и меню)
Дата: 2026-08-08
Методика: `2026-08-08-mo-analytics-mz-sheet-layers-v2.md`
Техническая реализация склада/API: `2026-08-08-mo-analytics-implementation-blueprint-v1.md`
Преемник для UI-частей blueprint §5–§10 (там было слишком много экранов и англ. ярлыков)

**Принцип:** меню и экраны только для ежедневной работы методиста.
Всё на русском. Нет «аналитики ради аналитики». Нет англ. Safety / Overview / Attention в UI.

---

## 1. Зачем продукт

Методист за 2–3 минуты должен ответить:

1. Что срочно разобрать сегодня?
2. Где провал: оформление, диагноз или план по протоколу?
3. Что именно не так в этом МО и какое решение записать?

Всё остальное - вторично и прячется.

---

## 2. Три оценки + риск (язык интерфейса)

| Что видит пользователь | Смысл | КП |
|--|--|--|
| **Оформление** | Заполненность МО по Инструкции №127 | нет |
| **Диагноз** | Клиника + МКБ, обоснованность | да |
| **План по протоколу** | Обследование, лечение, наблюдение, коррекции | да |
| **Риск** | Опасные сочетания, красные флаги | не % |

Состояния: **в норме** / **слабо** / **плохо** / **нет данных**
Для плана без подобранного КП: **протокол не подобран** (не «0%» и не «не по протоколу»).

Запрещены на главных экранах: «Итоговая», «Полнота» (если это coverage), «Соответствие №55» как главный балл, англ. названия зон.

## 3. Левое меню (короткое)

Только 6 пунктов. Без групп «Мониторинг / Работа / Аналитика».

| Пункт | Зачем |
|--|--|
| **Сегодня** | Стартовый экран: день, что делать |
| **Период** | Картина за выбранный месяц / диапазон |
| **Очередь** | Список на разбор |
| **Все случаи** | Поиск и фильтры по всем МО |
| **Врачи** | Кто тянет качество вниз |
| **Отчёты** | Выгрузки и журнал (как сейчас) |

Убрать из меню (не делать отдельных страниц):

- Специальности
- Диагнозы (treemap)
- Безопасность как отдельный раздел
- Качество данных
- Кабинет врача (отдельный вход expert остаётся, не в этом меню)
- Настройки как главная страница (легенда - ссылка внизу меню)

Фильтры сверху на всех экранах: период · филиал · специальность · врач.
По умолчанию только клинические приёмы.

## 4. Экран «Сегодня» (главный)

Один экран работы. Без лишних графиков.

### Верх - одна строка фактов
Записей вчера · оценено · свежесть данных
Мелко, без цвета «тревоги».

### Центр - куда смотреть (крупно, 5 плиток)

1. **Критично в очереди** - число, клик → Очередь (критично)
2. **Важно в очереди** - число, клик → Очередь (важно)
3. **Оформление плохо** - число и %
4. **Диагноз плохо** - число и %
5. **План по протоколу плохо** - число и %

Риск не отдельной шестой плиткой: критичные по риску уже входят в «Критично в очереди», с пометкой «риск» в причине.

Подсказка у плитки плана:
«Считается, если подобран клинический протокол. Жалобы и осмотр сюда не входят.»

### Таблица дня (сразу под плитками)

| Приоритет | Раздел | Визит | Пациент | Дата | Врач | Диагноз | Причина | История |
|--|--|--|--|--|--|--|--|--|

Раздел = Оформление / Диагноз / План по протоколу / Риск.
Клик по строке открывает разбор.
Не больше 30–50 строк по умолчанию (сначала критично и важно).

### Один простой график (внизу, компактно)

Три линии за 14 дней: среднее по оформлению, диагнозу, плану.
Нужен только чтобы видеть «вчера - выброс или тренд».
Клик по дню меняет дату «Сегодня».

**Не показывать на «Сегодня»:** воронку CRM, heatmap, четыре старые оси, чек-лист №55, топ findings Pareto, boxplot, treemap.

## 5. Экран «Период»

То же внимание, но за выбранный диапазон.

1. Те же 5 плиток (за период).
2. Тот же график трёх линий (за период).
3. Блок **«Куда смотреть»** - таблица, не scatter:

| Специальность или врач | Случаев | Оформление плохо | Диагноз плохо | План плохо | Открыть |
|--|--|--|--|--|--|

Сортировка по наибольшей доле «плохо» при достаточном объёме.
Клик «Открыть» → Все случаи с фильтром.

Сворачиваемый блок **«Подробнее»** (закрыт по умолчанию):

- Средний балл чек-листа №55 и частые провалы
- Среднее по методике «Как оценивать»
- Старые оси (deep) - только если включено в настройках

---

## 6. Экран «Очередь»

Рабочий список. Колонки только нужные:

| ☐ | Приоритет | Раздел | Визит | Пациент | Дата | Врач | Диагноз | Оформление | Диагноз | План | Причина | Статус |
|--|--|--|--|--|--|--|--|--|--|--|--|--|

Оценки в таблице - короткие метки: в норме / слабо / плохо / нет данных / протокол не подобран.
Не проценты в каждой ячейке (проценты - в разборе).

Фильтры слева или сверху (мало):

- Приоритет: критично / важно
- Раздел: оформление / диагноз / план / риск
- Протокол: подобран / не подобран
- Только без решения методиста

**Не раздувать whitelist:** в очередь не класть «слабо» по оформлению без реального пробела МО; план без протокола не штрафовать как «не по протоколу».

---

## 7. Экран «Все случаи»

Поиск и выборочный разбор.

Колонки по умолчанию:

Визит · Пациент · Дата · Врач · Диагноз · МКБ · История · Оформление · Диагноз · План · Причина внимания · Статус

Скрыто по умолчанию (можно вернуть в меню колонок): сводный индекс, №55, полнота проверки модели.

Фильтры те же + свободный поиск по визиту / пациенту / диагнозу.

---

## 8. Экран «Врачи»

Одна таблица + один простой график.

Таблица:

| Врач | Специальность | Случаев | Оформление плохо % | Диагноз плохо % | План плохо % | В очереди | Открыть случаи |
|--|--|--|--|--|--|--|--|

График: горизонтальные полосы «доля плохого» по выбранному разделу (переключатель: оформление / диагноз / план).
Без scatter «ожидаемое vs факт» на первом экране.

Клик по врачу → Все случаи с фильтром врача и «только плохое» по выбранному разделу.

## 9. Разбор случая (лаконичный)

Цель: за минуту понять проблему и записать решение.
Весь интерфейс только на русском. Без англ. ярлыков, без дублей одних и тех же баллов.

### 9.1 Порядок блоков (сверху вниз)

Широкая панель. Слева текст МО, справа - оценка и решение (на узком экране - столбиком в том же порядке).

| # | Блок | На первом экране |
|--|--|--|
| 1 | Шапка | да |
| 2 | Три оценки | да |
| 3 | Что не так | да |
| 4 | Текст МО | да |
| 5 | История пациента | кратко, да |
| 6 | Протоколы | одна строка, да |
| 7 | Решение методиста | да, закреплено снизу справа |
| 8 | Все критерии методики | нет - по кнопке «Подробнее» |
| 9 | Заключение ИИ | нет - внутри «Что не так» или «Подробнее» |
| 10 | Чек-лист №55, старые оси, CRM, пакеты | нет - в самом низу «Служебное» |

### 9.2 Шапка

Одна строка:

**Визит … · Пациент … · дата · врач · специальность**
Рядом диагноз и МКБ.
Если есть риск - красная метка **Риск** (одно слово).

Кнопки: предыдущий / следующий / закрыть / открыть PDF.

### 9.3 Три оценки

Три равные карточки, без процентов-шума на первом взгляде:

| Оформление | Диагноз | План по протоколу |
| в норме / слабо / плохо | то же | то же или «протокол не подобран» |

Под каждой - **одна** короткая фраза почему.
Клик по карточке фильтрует список «Что не так» этим разделом.

### 9.4 Что не так (главный рабочий блок)

Короткий список замечаний - только полезные:

- метка раздела: Оформление / Диагноз / План / Риск
- одна строка сути
- при необходимости ссылка «показать в тексте МО»

Фильтр-чипы: Все · Оформление · Диагноз · План · Риск.
По умолчанию: Все, но если открыли из очереди с разделом - сразу этот раздел.

Если есть заключение ИИ - не отдельная длинная секция, а до трёх строк внизу списка:

> ИИ: оформление - …; диагноз - …; план - …

Без отдельного «LLM KPI», без сравнения proxy vs LLM на первом экране.

### 9.5 Текст медицинского осмотра

Только поля с смыслом (не пустые «на печать»):

Жалобы · Анамнез · Осмотр · Клинический диагноз · Диагноз МИС · Обследования · План / рекомендации

Поля без текста - скрыты.
Подсветка поля, к которому относится выбранное замечание.

### 9.6 История - коротко

Не три длинные полки сразу.

Одна строка-сводка:

> К этому врачу: N · К специальности: N · Всего: N · Для коррекций плана: есть prior / нет prior

Раскрывается список прошлых визитов по клику.
Если prior нет - сразу пояснение: «Коррекции плана не оцениваются».

### 9.7 Протоколы - одна строка

- Есть: «Протокол: [короткое название]» + кнопка открыть (топ-1; остальные - «ещё N»).
- Нет: «Протокол не подобран - план не штрафуем за несоответствие протоколу.»

Без большого блока score/suggest на первом экране.

### 9.8 Решение методиста (всегда под рукой)

Форма короткая:

1. Оформление - вердикт (ок / замечание / не применимо)
2. Диагноз - вердикт
3. План по протоколу - вердикт
4. Комментарий (одно поле)
5. Статус разбора + **Сохранить**

Без отдельных CRM-шагов, сроков и «пакета обучения» на главном виде.

### 9.9 Подробнее (свёрнуто)

Открывается по желанию:

1. **Таблица критериев** - сначала только слабо/плохо/не оценивается; кнопка «показать все».
   Колонки: Параметр · Оценка · Что не так.
   (Регламент и «как оценивать» - подсказка по наведению или вторая строка, не пять колонок сразу.)
2. Заключение ИИ полностью (если было сжато выше).
3. Подобранные протоколы списком.

### 9.10 Служебное (свёрнуто в самом низу)

Чек-лист №55 · старые оси · служебные id / пакет для обучения.
Обычному разбору не мешают.

### 9.11 Что убрать из текущего разбора

| Сейчас мешает | В v2 |
|--|--|
| Много секций с похожими баллами | одни три оценки сверху |
| Отдельный большой блок ИИ | 3 строки в «Что не так» |
| Полная таблица 13 критериев всегда | только в «Подробнее», сначала проблемные |
| Длинные полки истории | сводка + раскрытие |
| Большой блок подбора КП | одна строка |
| №55 и deep на виду | в «Служебное» |
| Англ. названия, zone1, LLM, overall | только русские слова |
| CRM / обучение на первом экране | в «Служебное» |

### 9.12 Приёмка разбора

- Первый экран без прокрутки на 1440×900: шапка + 3 оценки + «Что не так» + начало текста + форма решения видна или в один скролл.
- Методист объясняет проблему своими словами за ≤ 30 секунд.
- Нет слова «не по протоколу» у жалоб/осмотра.
- Все видимые подписи на русском.

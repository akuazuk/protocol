# МО: конкретные решения перед изменением клинических баллов

Статус: проект инженерной спецификации для медицинского review, не утверждённая
клиническая методика и не юридическое заключение. 2026-09-06.
Связан с [полным аудитом](2026-09-06-mo-comprehensive-audit-and-roadmap.md)
и [tracker реализации](2026-09-06-mo-implementation-tracker.md).

## Что можно проверить программно сейчас

Передачу периода между UI/API, числовые значения и единицы анализов, даты,
принадлежность записи пациенту, сохранение нуля и unknown, повторный штраф,
отбор предыдущего визита, сохранение фильтра при переходе, происхождение
данных и отсутствие ошибок JavaScript. Именно эти свойства проверяются
текущими regression tests. Они не доказывают медицинскую правильность
диагноза или назначения и не дают основания объявить модель точной на 95%.

## Что должен утвердить клинический владелец

| Решение | Предлагаемое правило | Что требуется для утверждения |
|---|---|---|
| Применимость №55 | Отдельно буквальные критерии акта и внутренние аналоги; фиксировать редакцию/роль/условия помощи | Методист + правовая сверка действующей редакции и mapping ролей |
| Документы и помощь | Полнота заполнения не доказывает правильность клинического решения | По каждому критерию: какие доказательства достаточны, когда unknown |
| История | Более ранние релевантные факты учитываются; копирование старого текста не является выполненным действием | Границы эпизода, допустимая давность, правила стабильного состояния/ухудшения |
| Анализы | Заказ, результат, доступность врачу и интерпретация — отдельные состояния | Локальные референсы, источники единиц, клиническая значимость, сроки доступности |
| Лекарства | Назначение связано с конкретной целью, дозой, формой, путём и временем приёма | Официальная инструкция на дату, правила допустимых отклонений и ручной сверки |
| Неопределённость | Unknown/error не равны «норма», «неприменимо» или нулю | Как показывать неполный итог без выдачи подтверждённого соответствия |
| Влияние на балл | Новые клинические правила сначала в shadow, затем blind review и заранее определённый gate | Подписанная матрица правил/severity/weights и процедура отката |

Ранее опубликованный PDF №55 содержал поправки по №129/2024. Само наличие
копии в проекте не подтверждает отсутствие более поздних поправок. До
нормативного релиза проверить официальный источник, сохранить hash и даты
действия. Не выдавать внутренний specialist_amb_core analog за буквальную норму.

## Приёмочные ситуации для истории, анализов и назначений

Все строки ниже — требования к логике обработки данных, а не готовые решения
о качестве лечения конкретного пациента.

| Ситуация | Допустимое поведение | Недопустимое поведение |
|---|---|---|
| Более полный прежний визит относится к другой проблеме | Не использовать его для зачёта текущего эпизода | Начислить кредит за наличие любых прежних записей |
| Релевантных прошлых визитов несколько | Показать даты и основание выбора; использовать подходящий по времени контекст | Предпочесть самый длинный текст независимо от времени |
| История недоступна из-за ошибки источника | Отдельный статус доступности | Объявить пациента впервые обратившимся |
| Был ранний визит в тот же день, но времени нет | Зафиксировать недостаточную временную точность | Придумать порядок событий |
| Врач обоснованно сохранил прежний план | Оценить связь с состоянием и протоколом по утверждённому правилу | Требовать изменения лечения только потому, что визит повторный |
| Анализ только назначен | Статус заказа | Считать обследование выполненным |
| Результат стал доступен после визита | Исключить требование учесть его в том визите | Штрафовать врача за будущее знание |
| Есть только дата результата, без времени | Показать неопределённость доступности внутри дня | Утверждать, что результат точно был у врача |
| Нет единицы/возраста/применимого референса | Unknown для соответствующей интерпретации | Применить произвольную взрослую норму |
| Доза есть у одного из двух препаратов | Привязать дозу к своему назначению | Зачесть её второму препарату |
| В тексте отрицание или семейный анамнез | Сохранить subject/assertion, не приписывать состояние пациенту | Создать подтверждённое противопоказание по слову |
| Инструкция содержит детский подраздел | Интерпретировать область действия подраздела | Вывести общий запрет применения у взрослых |
| Не совпали слова диагноза и показания | Candidate для сверки, проверить сопутствующие цели/симптомы | Автоматически признать назначение неправильным |
| Неизвестна форма или редакция инструкции | Явная неоднозначность и список кандидатов в защищённом UI | Молча взять первый документ по INN |
| Один finding есть в primary и shadow | Одно предметное нарушение с происхождением | Двойной штраф за один факт |
| Нет findings, но checks не выполнены | Не оценено/недоступно | 100 баллов и «нарушений нет» |

## Как получить доказательство улучшения

1. До запуска выбрать правила, специальности, возрастные группы и границы
   исходов. Для каждого finding определить, что является подтверждением,
   опровержением и недостатком данных. Отдельно оценивать применимость нормы.
2. Собрать защищённый набор с текущим МО, историей на дату визита, доступными
   анализами и активными назначениями. В публичные PR идут только схема,
   synthetic fixtures и агрегаты; реальные тексты/идентификаторы остаются внутри контура.
3. Разделить пациентов и время между train/dev/holdout. История одного пациента
   не должна связывать train и holdout. Зафиксировать holdout до подбора prompts.
4. Два независимых профильных врача размечают случаи без подсказки итогов
   старого/нового scorer. Разногласия разбирает назначенный арбитр; причины
   сохраняются, а неоднозначные примеры не превращаются в искусственный consensus.
5. Сравнить старый и новый код на одном frozen snapshot. Записать SHA кода,
   версию правил/модели/источников, effective flags, failures и coverage.
6. Считать PPV, sensitivity, false findings на 100 МО, coverage/abstention,
   интервалы неопределённости и результаты по подгруппам. Для №55 дополнительно
   совпадение по каждому критерию, применимости и лишь затем итоговой сумме.
7. Проверить, что выигрыш не получен за счёт отказа оценивать трудные случаи,
   утечки будущих данных или снижения чувствительности к значимым ситуациям.
8. До primary подписать gate и rollback: какие показатели допускают включение,
   какая доля остаётся на ручной проверке, кто и по каким сигналам отключает правило.

В исходном плане предложен стартовый gate обычного нового finding: PPV ≥95%
при нижней границе 95%-интервала ≥90%, вместе с приемлемыми sensitivity и
coverage. Это предложение требует утверждения; оно не универсально и не
является нормой МЗРБ. Для высокорисковых ситуаций комиссия отдельно задаёт
допустимый риск пропуска. При недостаточном n правило остаётся shadow.

## Решения, которые ещё не получены

- Имя/роль клинического владельца и арбитра.
- Утверждённая действующая нормативная редакция и mapping пакетов проекта.
- Доступный состав разметчиков, объём и способ получения защищённого holdout.
- Утверждённые пороги, веса и список правил, которым можно влиять на primary.

Без этих решений можно продолжать технические исправления, схемы данных,
synthetic tests и shadow replay на разрешённом контуре. Нельзя считать
клиническую валидацию пройденной или заменять её оценками другой модели.
PR #113 с proxy calibration не является автоматически врачебным gold set.

# A/B: лексический поиск vs +dense (эмбеддинги)

Дата: 2026-07-01. Цель - в цифрах проверить, стоит ли включать dense-поиск по эмбеддингам на проде (варианты A/B из обсуждения деплоя векторного индекса).

## Методика

- Набор: 100 симптомных запросов, 19 специальностей (`tests/fixtures/symptom_icd_probe_100.jsonl`).
- Пайплайн: локальный full-режим (`scripts/run_symptom_icd_probe.py --local --with-protocols`), реальный поиск протоколов (шаг 4) + детерминированная AI-оценка релевантности.
- Единственное отличие между прогонами - `RAG_VECTOR_INDEX` (0 = лексический + Gemini ICD; 1 = то же + dense из `corpus_vector_index`, 83652 вектора, dim 3072).
- Индекс собран из `corpus_chunks_parts`.

## Результаты (100 запросов)

| Метрика | Лексический | +Dense | Дельта |
|---|---|---|---|
| ICD top-1 плаузибельный | 100.0% | 93.0% | -7.0 |
| Протоколов оценено | 100 | 93 | -7 |
| Avg AI-рейтинг протокола | 3.87/5 | 3.87/5 | 0.0 |
| Рейтинг >=4/5 | 91.0% | 90.3% | -0.7 |
| Top-1 специальность hit | 67.0% | 67.7% | +0.7 |
| Top-1 релевантен (AI) | 96.0% | 96.8% | +0.8 |

На завершившихся кейсах dense и лексический **статистически идентичны** (различия в пределах шума).

## Ключевая находка: dense ломает 7/100 запросов

7 запросов при включённом dense **воспроизводимо** теряют ICD полностью (пустой результат -> нет протокола, нет анализа). Перепроверка тех же 7 запросов:

| id | запрос | Лексический | +Dense |
|---|---|---|---|
| s14 | отит средний боль в ухе | H66.9, prot 4/5 | пусто |
| s41 | запор боль в животе 4 дня | K59.0, prot 4/5 | пусто |
| s71 | остеопороз перелом позвонка | M80.9, prot 4/5 | пусто |
| s79 | эндометриоз боли при менструации | N80.9, prot 4/5 | пусто |
| s96 | ожог руки кипятком | T23.0, prot 4/5 | пусто |
| s97 | инородное тело в дыхательных путях | T17.9, prot 4/5 | пусто |
| s98 | анафилаксия после укуса пчелы | T78.2, prot 4/5 | пусто |

Причинность подтверждена двойным прогоном (dense OFF -> все 7 OK; dense ON -> все 7 пусто).

## Вывод

- Текущий dense-индекс (из `corpus_chunks_parts`) **не улучшает** качество (0 прироста на 93 кейсах) и **активно ухудшает** (7/100 запросов теряют результат).
- Варианты **A** (апгрейд инстанса под этот индекс) и **B** (квантизация этого же индекса) развернут на проде индекс, который в замере вредит - не рекомендуются.
- Базлайн (лексический + Gemini ICD) уже близок к потолку: ICD top-1 100%, top-1 релевантен 96%, avg 3.87/5.

**Решение: dense не включать (вариант C - оставить лексический + Gemini).**

Если возвращаться к dense в будущем - только через переэмбеддинг актуального прод-корпуса `rich_chunks` (Путь 2: индекс по chunk_id + wiring в lazy-режим), и повторить этот A/B; но по текущим данным ожидаемый прирост незначителен.

# B2C: «Проверь своё заключение»

Отдельный продукт поверх **Protocol** (B2B: врачи, МИС, методслужба). Пациент получает понятный ответ: насколько заключение согласовано с **клиническими протоколами Минздрава РБ**, что заполнено и что стоит уточнить у врача - **без** диагноза и **без** силы МЭЭ.

**Статус репозитория:** MVP backend + PWA-витрина · июнь 2026  
**Tier API:** `P1` (L1 structured + alignment, без ЦИСЗ, send_gate и LLM/RAG)

| | B2B (Protocol) | B2C (этот контур) |
|---|----------------|-------------------|
| Кто | Врач, методист, МИС | Пациент, родственник |
| Вопрос | Можно подписать и отправить в ЦИСЗ? | Понятно ли, что врач учёл протокол? |
| Язык | gate_score, alignment, ЦИСЗ | Светофор, блоки, вопросы врачу |
| Данные | FHIR Bundle, полный КЗ | Фото/PDF КЗ, опц. бланки анализов |

## Технический контур (реализовано)

| Компонент | Путь |
|-----------|------|
| Сборка отчёта для пациента | `clinical_knowledge/patient_report.py` |
| Оркестрация P1 | `clinical_knowledge/patient_review.py` |
| Парсер анализов | `clinical_knowledge/lab_result_parser.py` |
| Сверка анализов с КЗ | `clinical_knowledge/patient_lab_crosscheck.py` |
| Сверка блока обследований | `clinical_knowledge/patient_exams_enrich.py` |
| Сверка с протоколом | `clinical_knowledge/patient_protocol_crosscheck.py` |
| API | `rag_server.py` - `/api/patient/*` |
| PWA-витрина | `patient.html`, `patient-manifest.webmanifest`, `patient-sw.js` |
| Тесты | `tests/test_patient_report.py`, `tests/test_lab_result_parser.py` |

### Tier P1 - что входит в прогон

1. `run_l1_structured_review` - 8 блоков structured, alignment, без CISZ.
2. `build_patient_report` - светофор, 8 блоков простым языком, `questions_for_doctor`, цитаты.
3. Опционально `crosscheck_labs_with_kz` при загрузке `lab_files`.
4. `sanitize_patient_api_payload` - B2B-поля (send_gate, cisz_readiness и т.д.) не отдаются клиенту.

## Отличия от веб-Protocol (B2B)

B2C **не** вкладка в `index.html` для врача. Отдельно:

- упрощённый отчёт без Methodist, training cases, send_gate, ЦИСЗ;
- отдельные лимиты и namespace API;
- свой бренд/витрина (`patient.html`, в перспективе нативное app);
- пациент не видит gate_score и внутренние alignment-карточки - только перевод в `patient_report`.

---

## Дисклеймер (обязателен в UI и API)

Ориентировочная сверка с клиническими протоколами Минздрава РБ. Не является диагнозом, медицинским заключением или заменой очного приёма. При сомнениях обратитесь к лечащему врачу или методслужбе клиники.

Константа в коде: `PATIENT_DISCLAIMER_RU` в `patient_report.py`.

## 1. Контекст: две поверхности, одна из них - витрина под данные, которых нет

Сейчас MIS · КЗ живёт в двух местах с расходящейся логикой:

- **Вкладка в кабинете** (`index.html`, `#methodist-mis-kz-root`): сводка из summary.json -
  KPI, «Гигиена данных», №55, сравнение месяцев, таблицы специальностей и врачей,
  топ-50 слабых визитов, LLM-разбор. Фильтров нет. Данные L1 - работает.
- **Отдельный дашборд** (`mis-kz-quality.html`): богатая система §7Б - месяцы-пилюли,
  активный месяц, ~15 фильтров, таблица кейсов с пагинацией/фасетами, динамика, разбор
  кейса. Бэкенды: `/cases`, `/dynamics`, `/scoring-info`, `/case-detail`.

**Корневая проблема:** дашборд построен под вывод deep-eval (оси A/B/C/D, находки,
severity P0-P3, potential_harm, needs_human, код МКБ, agreement, возраст), а реально
загружены только L1-данные. Половина фильтров и диаграмм привязана к пустым полям.

## 3. Ключевая находка: часть «мёртвых» фильтров оживляется БЕЗ БД

- **Код и глава МКБ** извлекаются детерминированно из текста диагноза КЗ (в `cases.jsonl`
  диагноз содержит коды, напр. `I67.1|G93.0|G44.2`; L2-парсер уже это умеет через
  `icd_mkb`). Значит `mkb_chapter`, отчёт «по главам МКБ», пресет `dx_no_code` и частично
  `mkb_agreement` (код в тексте vs структурный код МИС) можно активировать **сейчас**.
- **Возраст** требует DOB из БД (ре-экспорт) - остаётся на deep-eval-план.
- **Оси / findings / severity / potential_harm / needs_human** - только после deep-eval
  (это `kz-deep-eval-db-task-v1.md`).

## 7. Критерии приёмки по отчётам (тест-план)
- **KPI:** числа сходятся с агрегатом активного месяца; при смене месяца/фильтра
  пересчитываются.
- **Гигиена данных:** сумма долей = 100%; «оцениваем/не оцениваем» согласовано с N.
- **№55:** доля выполненных критериев ∈ [0..100], топ-невыполненных отсортирован.
- **Сравнение месяцев:** Δ = compare - base с верным знаком; спец. ↑/↓ корректны.
- **Специальности / Врачи:** N, avg, min/max; сортировка; drill-down врача открывает его
  кейсы с фильтром.
- **Филиалы:** N и avg по каждому; сумма N = N месяца.
- **Топ-50:** сортировка по возрастанию скора; чекбоксы → LLM-прогон с прогрессом;
  колонка №55 и L2 заполняются.
- **Таблица кейсов:** каждый рабочий фильтр меняет `total` и агрегат; пагинация; сорт по
  столбцам; `q` ищет по коду и тексту диагноза.
- **Разбор кейса:** оси/находки/block_scores/№55 совпадают с `case-detail` и с живым L2.
- **Каждый неактивный фильтр:** виден как `disabled` с причиной, не отдаёт пустой список
  молча.

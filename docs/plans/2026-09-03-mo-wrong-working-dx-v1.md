## 1. Класс ошибки (не «нет рентгена в КП миозита»)

Это не дыра «КП M60 требует рентген». КП миозита рентген таза не требует.

Это **внутренне согласованный ложный рабочий диагноз**:

1. Текст диагноза и код **совпадают** (M60 + «миозит прямой мышцы»).
2. В статусе есть локальная находка, которая **кормит** этот диагноз (боль при пальпации мышцы).
3. Презентация **не закрыта** диагнозом: ребёнок, хромота ≥4 нед, необъяснённый отёк сустава, нет imaging.
4. Обследования в этом МО **не доказывают** пропущенную нозологию (Пертес) и **не исключают** её: слота `exam_data` нет, план обследования пустой, ТБС записан «полный объём, безболезненны».
5. Система ставит зону «Диагноз» 100% и overall «хорошо», потому что проверяет оформление цепочки, не клиническую опору.

Юридически/по КП: рентген прямой + Лауэнштейн - это объём **M91.1** (прил. 1 КП 2024 №109), не пункт «при миозите». В аналитике нельзя писать «врач нарушил КП миозита, не сделав рентген». Нужно: «презентации достаточно, чтобы не останавливаться на M60 без исключения DDx».

## 2. Почему текущая аналитика это пропускает

Доказано на живом эталонном визите (warehouse GCE, 2026-08-31):

| Слой | Что случилось | Почему |
|--|--|--|
| Рубрика / zone2a | `diagnosis` = 1.0, «Диагноз с МКБ и клинической цепочкой» | `_score_diagnosis`: текст + код + ≥2 непустых слота (жалобы/анамнез/статус) → 1.0. Не проверяет, что диагноз **покрывает** находки |
| МКБ-чип | «МКБ ✓» | Справочник: M60 существует и совпадает с формулировкой. Это контур B, не клиника |
| Suggest | «Нет клинического протокола МЗ по этому диагнозу», query = текст миозита | Правило другой ветки: КП **по написанному Dx**, не выдумывать КП. Для M60 честный пустой/SSTI. Детский орто КП №109 не должен приходить «по миозиту» |
| План по протоколу | zone2b n/a, «протокол не подобран - не штрафуем» | Пустой suggest снимает штраф плана. Ложный рабочий Dx превращается в защиту врача |
| Concordance | `finding_not_in_diagnosis` P1, `underworkup` P2 - shadow | Не режут overall 83.5 / статус good |
| `pediatric_limp_ddx_not_addressed` | **не сработал** | В `record` нет `patient_age_years` (в МИС возраст 9 был). Fixture ловит, live - нет |
| exam_data | n/a «пациент ничего не принёс» | Верно как оформление. Нельзя читать как «обследования исключили Пертеса» |

Это **не** повод вернуть ICD-first suggest (омнибус/SSTI по M60). Задание другой ветки остаётся: КП по диагнозу в МО, возраст с ДР, КП в силе на дату визита.

## 3. Целевая модель: три канала, не один балл

```text
A. КП по написанному диагнозу     (ветка точности КП)     не балл врача
B. МКБ ↔ справочник               (directory eval)        отдельный чип
C. Презентация / DDx overlay      (этот план)             findings + очередь, не подмена A
```

| Канал | Вход | Выход на эталонном визите | Штраф врача? |
|--|--|--|--|
| A | «миозит прямой мышцы» | пусто или слабый SSTI; честно | нет (нет КП по этой формулировке) |
| B | M60 + текст | ok | нет, код валиден |
| C | возраст + хромота 3 мес + отёк колена + нет imaging | семейство: детская ортопедия / ЮА; finding underworkup + limp DDx | да, по клинике, **не** «не тот PDF» |

Канал C **не** ставит диагноз Пертес и **не** подменяет A в UI как «подобранный КП случая». Это блок «что ещё открыть / что не закрыто презентацией».

История визитов (задание другой вкладки): более поздний M91.1 у того же `patient_id` **не переписывает** оценку 10.06. Он даёт контекст эпизода: `history_continuity` / «позднее установлен M91*». Official score дня остаётся за тот визит.

## 4. Что менять в оценке и аналитике

### 4.1 Возраст (P0, стык с другой веткой)

Шаг 1 плана KP v2 не закрыт в live case detail: suggest и concordance не видят 9 лет.

- Считать `patient_age_years` на **дату визита** из `patient_bdate` (МИС / secure_cases / warehouse).
- Прокинуть в `record`, `clinical_case_from_document`, fact graph, №55 router (педиатр vs специалист).
- Не печатать ДР в логах/PR.
- Цель: ≥95% clinical CSV с возрастом; на эталонном визите срабатывает `pediatric_limp_ddx_not_addressed`.

### 4.2 Диагноз: оформление ≠ опора (P0)

`_score_diagnosis` (и zone2a) не должен давать 1.0, если есть concordance P1 `finding_not_in_diagnosis` или `icd_weakly_supported` при red-flag презентации.

| Слой | Правило |
|--|--|
| Методика «диагноз + МКБ в МО» | остаётся про наличие текста и кода |
| Клиническая опора | отдельный подбалл / cap: при P1 находка-не-в-диагнозе zone2a ≤ 0.5 |
| МКБ-чип | не менять смысл (справочник) |
| UI разбора | уже есть `clinical_support: weakly`; **overall / attention** должны это видеть |

Не ставить P0 «это Пертес». Ставить: диагноз не закрывает презентацию.

### 4.3 План обследования vs «нет данных обследований» (P1)

- `exam_data` n/a - ок, если ничего не принесли.
- `exam_plan` = 0 при хронической педиатрической хромоте / отёке сустава без imaging в плане - **primary**, не только shadow.
- Follow-up только «при отрицательной динамике» - fail кратности (№55 C7 уже 0 на этом кейсе). Сохранить.
- Не штрафовать «нет рентгена по КП M60». Штрафовать «нет плана исключения DDx при red-flag».

### 4.4 Suggest: не ломать A, добавить C (P1)

Не смешивать в одном top-1:

- Список «КП по установленному диагнозу» - как в другой ветке (возраст, in-force, без омнибуса, пусто если нет).
- Второй блок «По презентации (не замена диагноза)»: жалобы + статус + возраст + длительность. Для эталонного визита: КП 2024 №109 (детская ортопедия, M91.1 в предмете) и/или детский ревмо (ЮА), **ниже** и с бейджем `ddx` / `presentation`.

Finding `likely_missed_protocol_family` (E4 Смирновой): informational, **не** режет №55 «лечение по КП», пока Hit@3 канала C не калиброван. Иначе снова накажем врача за «не тот PDF».

### 4.5 Очередь и дашборд (P1)

Новый attention / фильтр (имя рабочее): `presentation_dx_gap`.

Включение: pediatric (или age unknown + жалобы ребёнка) **и** (`pediatric_limp_ddx_not_addressed` **или** (`finding_not_in_diagnosis` + `underworkup_chronic_red_flag`)).

Не класть в critical только из-за M60 у взрослых без хромоты.

KPI на Обзоре (месяц):

- доля МО с `presentation_dx_gap`
- среди них: доля с пустым suggest A
- overall/zone2a «ok» при наличии P1 concordance (false-green)

Таблица дня: колонка/чип «диагноз не закрывает презентацию», не дубль №55 %.

### 4.6 №55

Не плодить вторую рубрику. Section pack уже считает C1/C4/C7.

- C1 (план обследования): при канале C red-flag не оставлять 0.5 «сверка с КП неизвестна», если imaging нет совсем → 0.
- C2 (диагноз+МКБ из клиники): не 1.0 при P1 находка-не-в-диагнозе (частично / 0.5).
- C4: не штрафовать «не тот КП Пертеса», пока A пустой; можно 0.5 за план без разгрузки/контроля при limp.
- Историю эпизода в знаменатель дня не тащить (другая вкладка просила учитывать историю - только как evidence helper, как №127).

## 8. Definition of Done

1. Live эталонный визит: возраст 9, limp DDx finding есть, zone2a/diagnosis не 1.0, overall не «хорошо» без внимания.
2. Suggest A по-прежнему не выдаёт КП Пертеса «по миозиту».
3. Suggest C показывает детский орто/ревмо overlay с пометкой ddx.
4. Фильтр очереди ловит gold и не ловит чистый взрослый M60.
5. Handoff + обновление статусов в этом файле и в E4 Смирновой.
